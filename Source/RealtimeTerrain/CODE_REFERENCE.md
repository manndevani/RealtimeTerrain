### Source/RealtimeTerrain/Public/RealtimeRoadSplineActor.h
**Class/struct(s):** `ARealtimeRoadSplineActor` (UCLASS, Blueprintable); nested `FRoadRun` (protected plain struct, not a USTRUCT); free delegate `FOnRoadMeshUpdated`.
**Purpose:** Declares the runtime road actor that sweeps a solid cross-section along a spline, sampling GRT terrain per swept station so the road follows the landform at mesh resolution rather than only at spline control points. It is the single actor type for both paved and rough roads, replicated, and edited live via a settle-delay rebuild scheme.
**Key API / responsibilities:**
- `SplineComponent`/`RoadMeshComponent` (UDynamicMeshComponent)/`ScatterHISMComponent`/`PierHISMComponent` — root spline (XY route only) plus the swept mesh, prop-scatter HISM, and pier-support HISM.
- `RoadType`, `CrossSectionSettings`, `ScatterSettings`, `StylePreset`, `HeightKeys`, `WidthKeys`, `PierSettings`, `bUseSpiralCentreline`/`SpiralCornerMaxRadius`/`SpiralCurvatureBlend` — all `ReplicatedUsing = OnRep_RoadConfig` — the full authored configuration surface.
- `bAutoFlyover`, `MaxComfortableGradeDegrees`, `MinFlyoverRunLength` — auto-bridging controls feeding `RoadElevationProfile::DetectFlyoverBridges`.
- `bConformToTerrainInRealtime`, `TerrainSurfaceOffset`, `TerrainSmoothingSamples`, `bRoughRoadFollowsCrossSlope`/`MaxCrossSlopeDegrees`, `MaxPavedCrossSlopeDegrees` — terrain conforming/cross-slope banking knobs.
- `bRebaseTerrain`, `PadWidthMargin`, `PadFalloff`, `PadSampleSpacing`, `PadDepthBelowSurface` — pad-layer terrain leveling under the road.
- `SetWidthMultiplierAtDistance`/`GetWidthMultiplierAtDistance` — write/read path for `WidthKeys`, driven by the gizmo's Scale mode.
- `ReplicatedWorldPoints` + `OnRep_SplinePoints`/`OnRep_RoadConfig`/`OnRep_JunctionCuts` — replication plumbing.
- `AddJunctionCut`/`RemoveJunctionCutsFor`, `JunctionCuts` (`TArray<FRoadJunctionCut>`), `JunctionBlendStations` — junction-cut mechanism letting one road pass through multiple intersections without being split into separate actors.
- Realtime editing API: `SetIsHolographicPreview`, `AddPointRealtime`, `SetPointsRealtime`, `MovePointRealtime`, `ClearPointsRealtime`, `ExtendFromPointToLocation`, `BranchRoadFromPoint`, `InsertPointAtDistance`, `FindClosestSplinePoint`, `GetSplinePointWorldLocation`, `RebuildRoad`, `RequestRebuild`, `RefreshAffectedJunctions`, `SampleTerrainHeightAtXY`, `CanEditPoints`.
- `ApplyElevationProfile` (BlueprintCallable, public despite being an internal step) — applies HeightKeys/auto-flyover to a point array in place.
- `GetDrivingLaneCount`/`GetDrivingSurfaceHalfWidth` — style-aware lane/width queries used by junction ramp/fork classification.
- `#if WITH_EDITOR` `ExportRoadToXodr` — editor-only OpenDRIVE export.
**Dependencies:** `RoadTypes.h`, `RoadElevationProfile.h`, `RoadWidthProfile.h`, `RoadPierPlacement.h`, `RoadSpiral.h`; forward-declares `USplineComponent`, `UDynamicMeshComponent`, `UHierarchicalInstancedStaticMeshComponent`, `ARealtimeRoadJunctionActor`, `AGRTManager`, `URoadStylePreset`, and `RoadMesh::FFrame`.

### Source/RealtimeTerrain/Private/RealtimeRoadSplineActor.cpp
**Class/struct(s):** `ARealtimeRoadSplineActor` (implementation).
**Purpose:** Implements the full road actor: point editing/branching, terrain-conformed centreline construction (with optional spiral-fit corners), junction-cut-based run splitting, cross-section sweeping into a `UDynamicMesh`, cross-slope banking, terrain pad rebasing, scatter/pier instancing, and `.xodr` export.
**Key API / responsibilities:**
- Constructor wires up components and loads default materials via `ConstructorHelpers::FObjectFinder` (CitySample asphalt/curb/sidewalk, a Proto rough-road material, and a holographic material) — all still per-instance overridable.
- `GetLifetimeReplicatedProps` replicates `RoadType`, `CrossSectionSettings`, `ScatterSettings`, `StylePreset`, `HeightKeys`, `PierSettings`, `WidthKeys`, `bUseSpiralCentreline`, `ReplicatedWorldPoints`, `JunctionCuts`.
- `BeginPlay`/`EndPlay`/`Destroyed`/`OnConstruction` — sync spline from replicated points then `RebuildRoad()`; `EndPlay`/`Destroyed` both call `ClearTerrainPad()` so a road removed any way still returns the terrain.
- `CanEditPoints()` — true for a holographic preview or the authority; logs a warning and refuses on a client otherwise, directing edits through `URealtimeRoadBuilderComponent`.
- `SyncSplineFromReplicatedPoints`/`CaptureReplicatedPoints` — mirror `SplineComponent` <-> `ReplicatedWorldPoints`, with points set as `ESplinePointType::CurveClamped`.
- `SetIsHolographicPreview` — toggles collision off/no-replication for a ghost, restoring replication and re-capturing points when turned off.
- `AddPointRealtime`/`SetPointsRealtime`/`MovePointRealtime`/`ClearPointsRealtime`/`InsertPointAtDistance` — direct spline mutators, all gated by `CanEditPoints()`.
- `ExtendFromPointToLocation` — interpolates new points at `MaxSegmentSpacing`, seeding each with sampled ground height + `TerrainSurfaceOffset`; branches via `BranchRoadFromPoint` for an interior `FromPointIndex` rather than extending in place; reports which actor/point actually grew.
- `BranchRoadFromPoint` — calls `RoadNetwork::CreateJunctionOnRoad` to spawn a junction at the branch point, then spawns a new road actor copying the parent's road-type/cross-section/scatter/pier/terrain settings and pins its start to the new leg socket.
- `BuildConformedCentreline` — the core sampling loop: optionally builds XY via `RoadSpiral::BuildSpiralCentreline` (settle-pass only, gated by `bAllowSpiralFit && bUseSpiralCentreline`), else falls back to even-step spline sampling; when terrain-conforming, calls `RoadMesh::SmoothHeights`, adds `TerrainSurfaceOffset`, then `ApplyElevationProfile`.
- `ApplyElevationProfile` — merges `HeightKeys` with `RoadElevationProfile::DetectFlyoverBridges` output (auto-bridge only where no user key already overlaps that stretch), then overwrites `Points[i].Z` via `RoadElevationProfile::EvaluateHeight` wherever a distance falls inside the merged key range.
- `BuildRuns` — sorts `JunctionCuts` by `EntryDistance`, walks stations splitting them into `FRoadRun`s around each cut, skipping stations inside `[EntryDistance, ExitDistance]`, then calls `PinRunEnds` on every run.
- `PinRunEnds` — blends a full correction at a pinned end tapering to zero over `JunctionBlendStations` stations so a socket-pinned end doesn't kink.
- `ComputeCrossSlopeRoll` — computes per-frame roll: rough roads bank per `bRoughRoadFollowsCrossSlope`/`MaxCrossSlopeDegrees`; paved roads bank only where BOTH lateral samples land on non-GRT ground (Cesium tile terrain), capped by `MaxPavedCrossSlopeDegrees`, then box-smoothed by `TerrainSmoothingSamples`.
- `GenerateRoadMesh` — builds centreline+runs, builds `RoadMesh::FSection` either from `StylePreset` (`BuildRoadSectionFromStyle`) or `CrossSectionSettings` (`BuildRoadSection`), computes per-frame band scale from curvature (`ComputeBandScaleFromCurvature`) and per-frame width scale from `WidthKeys` (`RoadWidthProfile::EvaluateWidth`, re-based to each run's global distance via `Run.StartDistance + Frame.DistanceAlong`), sweeps every run into one `UDynamicMesh` via `RoadMesh::SweepSection`, computes split normals, and defers collision cooking unless `bUpdateCollision`.
- `RebuildRoad()`/`RequestRebuild()`/`RebuildInternal` — full vs. deferred-collision rebuild; `RequestRebuild` sets `SettleTimerHandle` to call `RebuildRoad` after `SettleDelaySeconds`.
- `UpdateTerrainPad`/`ClearTerrainPad` — pushes level pad-quad stamps (union of previous+current bounds) to `AGRTManager::SetExternalPadStamps`/`GetExternalPadBounds`/`RefreshBuildingPads`; each stamp's `TargetWorldZ` uses the *lower* of the span's two endpoint heights (not the mean) minus depth, specifically to avoid the ground breaking through a sloped road.
- `GenerateScatter`/`GeneratePiers` — HISM instancing driven by `ScatterSettings`/`PierSettings`, the latter delegating placement decisions to `RoadPierPlacement::PlacePiers`.
- `RefreshAffectedJunctions(bFullNetworkReconcile)` — rebuilds junctions this road is pinned to or newly overlaps, then either `RoadNetwork::RebuildIntersections` (full) or `RoadNetwork::RebuildIntersectionsNear` (drag-scoped).
- `GetDrivingLaneCount`/`GetDrivingSurfaceHalfWidth` — style-aware (from `StylePreset`) else fallback (2 lanes paved / 1 rough; half of `CrossSectionSettings.RoadWidth`).
- `#if WITH_EDITOR` `ExportRoadToXodr` — builds `RoadXodrExport::FRoadExportData` from the conformed centreline, `HeightKeys`, and either the style's lane list or a synthesized 1-2 lane fallback; writes to `Saved/Export/<Label>.xodr`.
**Dependencies:** `RealtimeRoadJunctionActor.h`, `RoadMeshBuilder.h`, `RoadNetwork.h`, `EngineUtils.h`, `Components/SplineComponent.h`, `Components/HierarchicalInstancedStaticMeshComponent.h`, `Components/DynamicMeshComponent.h`, `UDynamicMesh.h`/`DynamicMesh3.h`, `GeometryScript/MeshNormalsFunctions.h`, `Core/GRTManager.h`, `Net/UnrealNetwork.h`; editor-only `RoadXodrExport.h`.
**Notable implementation details:** Re-entrancy/ordering invariants throughout — junction pinning happens after smoothing so it can't be dragged off-socket; `Options.WidthScalePerFrame`/`Options.BandScalePerFrame` are rebuilt fresh per run inside the sweep loop since `Options` is reused across runs; scatter/piers are skipped and instances cleared (not left stale) during a non-settled drag to avoid props visibly stranding off the moving road; `SortedWidthKeys`/`EffectiveKeys` are defensively re-sorted at use time since the UPROPERTY arrays are directly user-editable, not just gizmo-written.

### Source/RealtimeTerrain/Public/RealtimeRoadJunctionActor.h
**Class/struct(s):** `ARealtimeRoadJunctionActor` (UCLASS, Blueprintable).
**Purpose:** Declares the intersection actor — a filleted-polygon slab derived either from authored `Legs` or (preferred) from roads actually found passing through a bounding radius, planar by design but height-sampled from terrain/connecting roads, exposing leg sockets that connecting roads pin to.
**Key API / responsibilities:**
- `JunctionType` (preset enum), `RoadWidth`, `CornerFilletRadius`/`FilletSegments`, `CurbHeight`/`CurbWidth`/`FootpathWidth`/`FootpathHeight`, `RoadThickness`, `UVTilingScale` — all `ReplicatedUsing = OnRep_JunctionConfig`.
- `bSolveFromNearbyRoads`, `bAutoGenerated`, `BoundsRadius`, `CornerReturnRadius`, `CornerArcSegments` — the bounding-volume solve workflow controls.
- `SolveIntersection()` — rebuilds `Legs` and surface from roads currently inside the bounds and writes trim distances back as junction cuts; returns false when fewer than two arms found.
- `IsAnySolveInProgress()` (static) — re-entrancy guard exposed so a rebuilding road doesn't recursively re-trigger a solve.
- `Legs` (`TArray<FRoadJunctionLeg>`, `ReplicatedUsing = OnRep_Legs`).
- `bConformToTerrain`, `TerrainSurfaceOffset` — terrain plane-height controls.
- `SetIsHolographicPreview`, `RebuildJunction`, `SyncPresetLegs` (no-op for `Custom_N_Way`), `AddLegRealtime`, `FindClosestLeg`, `GetLegConnectionTransform` (socket transform for a leg), `GetLegWidth`, `GetRampCornerCount`, `GetConnectorCount`.
**Dependencies:** `RoadTypes.h`; forward-declares `UDynamicMeshComponent`, `UMaterialInterface`, `ARealtimeRoadSplineActor`, `AGRTManager`.
**Notable implementation details:** Private cached solve state — `SolvedBoundary`, `SolvedRoadsideChains`, `SolvedCornerRadii`, `SolvedIsRampCorner`, `SolvedGoreApex`, nested `FSolvedLaneConnector` struct + `SolvedConnectors`, `SolvedLegHeights` — is entirely non-replicated, per-instance-computed state from the last successful `SolveIntersection()`. `bLastSolveWasOrphaned` distinguishes "just-placed junction with nothing nearby yet" from "previously-solved junction that lost its connections", which `RebuildJunction` uses to decide whether to self-destroy.

### Source/RealtimeTerrain/Private/RealtimeRoadJunctionActor.cpp
**Class/struct(s):** `ARealtimeRoadJunctionActor` (implementation); file-local `FResolvedLeg` struct and `Cross2D`/`StraightGapThresholdDegrees` helpers.
**Purpose:** Implements junction boundary construction (both the authored-legs fallback and the roads-solved-from-bounds path), the corner fillet/gore/lane-connector geometry, terrain plane resolution, and the road-cut writeback that keeps connected roads pinned through the intersection.
**Key API / responsibilities:**
- Constructor loads the same CitySample material defaults as the road actor and calls `SyncPresetLegs()`.
- `PostEditChangeProperty` (`WITH_EDITOR`) — calls `SyncPresetLegs()` when `JunctionType` changes in the editor.
- `SyncPresetLegs` — fixed angle lists per preset: T_Junction `{0,90,270}`, Cross_4Way `{0,90,180,270}`, Y_Fork `{0,135,225}`; `Custom_N_Way` leaves `Legs` untouched.
- `GetLegConnectionTransform` — socket location uses `SolvedLegHeights[LegIndex]` when available (each arm's own height) else falls back to `ConformedPlaneWorldZ`, specifically to avoid a road stepping up/down when approaching a sloped intersection.
- `ResolvePlaneWorldZ` — averages terrain samples at the actor centre and every leg-arm end, plus `TerrainSurfaceOffset`; falls back to authored actor Z if no samples land.
- `BuildBoundary` — authored-`Legs` fallback path: sorts legs by angle, for each adjacent pair computes a rounded corner by intersecting the two legs' offset edges, clamping the fillet radius against arm length and against `CornerFilletRadius`; falls back to a single bisector point when legs are near-opposite (`StraightGapThresholdDegrees = 178°`) or the corner geometry is degenerate. Reports `OutMaxBandWidth` as the tightest corner's radius / `RoadMesh::BandRadiusSafetyFactor` so curb/footpath bands can be scaled to fit.
- `SolveIntersection` — guarded by static `bAnySolveInProgress` (`TGuardValue`) against recursive re-entry from road rebuilds; scans all `ARealtimeRoadSplineActor`s in the world via `TActorIterator`, finds each road's node-distance via `RoadNetwork::FindDistanceAlongRoad2D`, builds up to two `RoadNetworkSolver::FArm`s per road (forward/backward) each anchored exactly at the node centre (not the road's own closest point, which previously desynced arm origins and tore intersections apart) and sampled outward in `SampleStep` increments to `SampleReach = Radius*2.5`; calls `RoadNetworkSolver::SolveNode`. On fewer than 2 arms, sets `bLastSolveWasOrphaned=true` and, if exactly one road remains, un-pins it (`RemoveJunctionCutsFor`, clears `StartJunction`/`EndJunction`) rather than leaving it cut short. On success, derives per-arm terrain heights, blends `HeightAt` across boundary vertices, builds gore fills (`RoadNetworkSolver::FindGoreApex`) at ramp corners (falling back to "not a gore" if the apex can't be found), builds per-lane connectors via `RoadNetworkSolver::MapLaneConnections`/`BuildLaneConnectorCentreline` with a small `ConnectorLift` to avoid z-fighting, and rewrites `Legs` + calls `AddJunctionCut`/sets `StartJunction`/`EndJunction` on each connected road.
- `RebuildJunction` — prefers the solved-from-nearby-roads path; if `bLastSolveWasOrphaned` and `JunctionType == Custom_N_Way` with no geometry, calls `Destroy()`; otherwise falls back to `BuildBoundary`. Builds the mesh via `RoadMesh::AppendPrism` for the slab, `RoadMesh::AppendGoreFill` at ramp corners, `RoadMesh::SweepSection` for lane connectors and for the curb/footpath band (scaled per-corner by available radius vs. `RequestedBand`).
**Dependencies:** `RoadMeshBuilder.h`, `RoadNetworkSolver.h`, `RoadNetwork.h`, `RealtimeRoadSplineActor.h`, `Components/SplineComponent.h`, `EngineUtils.h`, `Algo/Reverse.h`, `Components/DynamicMeshComponent.h`, `UDynamicMesh.h`/`DynamicMesh3.h`, `GeometryScript/MeshNormalsFunctions.h`, `Core/GRTManager.h`, `Net/UnrealNetwork.h`.
**Notable implementation details:** Both `BuildBoundary`'s corner chains and the solved `SolvedRoadsideChains` are `Algo::Reverse`d before use because swept frames take `Right` from world-up crossed with tangent, which points inward along the counter-clockwise boundary traversal — reversing turns it outward to match how the roadside section is authored. Per-corner band-width clamping (rather than one junction-wide minimum) is deliberate: a single tight corner used to strip curbs/footpaths from every corner on the junction.

### Source/RealtimeTerrain/Private/RealtimeRoadBuilderComponent.cpp
**Class/struct(s):** `URealtimeRoadBuilderComponent` (implementation).
**Purpose:** Implements the full interactive road-editing tool: per-tick drag driving (gizmo or free ground-follow), overlay/hover management, undo/redo snapshotting, click-routing between select/extend/branch/start, junction snapping, and the client-to-server road/junction commit RPC path.
**Key API / responsibilities:**
- `TickComponent` — fail-safe ends a drag if the left mouse button is no longer down (guards against Slate/UI swallowing the mouse-up); while dragging, either feeds `GizmoSubsystem->UpdateManipulation` (gizmo drag, with Ctrl held inverting snap) or moves the point along a ground trace + `DragGrabOffset`; throttles junction re-solve to `JunctionResolveInterval` via `RefreshAffectedJunctions(false)` (drag-scoped); always calls `UpdateEditOverlay()`/`UpdatePointGizmo()`.
- `EndPlay` — destroys `EditOverlay`; clears the shared gizmo subsystem's target only if it's still bound to this component's own road (never destroys the shared gizmo actor itself).
- `TraceHandleUnderCursor` — multi-hit line trace (`LineTraceMultiByChannel`, `ECC_Visibility`) so an overlay handle rendered through terrain (`SDPG_Foreground`, no depth test) can still win the hit-test even when it's occluded on screen.
- `TraceGroundUnderCursor` — single-hit trace on `ECC_WorldStatic`, ignoring the overlay actor, gizmo actor, selected road, and active draft road.
- `UpdateEditOverlay` — resolves the overlay's target road (selection, else draft, else whatever's hovered over via `FindRoadLineNear`), rebuilds overlay instances only on target change or while dragging (not every tick for a static spline), sets selected/highlighted point.
- `UpdatePointGizmo` — lazily fetches `UGizmoManipulationSubsystem` and subscribes to `OnManipulationCancel`; rebinds the subsystem's get/set transform closures only when selection actually changes. The get-closure returns the point's world location (offset by `EditOverlay->VerticalOffset` to match the visible handle) with `Scale3D` set from `GetWidthMultiplierAtDistance` — i.e. Scale mode's meaning for a road point is literally the width-profile multiplier. The set-closure calls `MovePointRealtime`, and additionally calls `SetWidthMultiplierAtDistance` but ONLY when `GizmoSubsystem->GetMode() == EGizmoMode::Scale` (gated specifically so a Translate drag, whose distance-along-spline changes every frame, doesn't spam junk width-key entries).
- `BeginPointDrag` — gizmo handle takes priority (re-traced fresh each press, not last-tick's hover state, to avoid acting on stale hover after a fast cursor move); otherwise requires a fresh handle trace to succeed at all (no drag starts from empty ground); a first press on an unselected handle both selects and begins dragging it in one motion (explicitly rejecting the old two-press "safety" as unnecessary friction, since the grab-offset makes a stationary click move nothing).

### Source/RealtimeTerrain/Private/RoadNetworkSolver.cpp
**Class/struct(s):** none (implements `RoadNetworkSolver` namespace; local anonymous-namespace helpers `Cross2D`, `LeftNormal`, `SegmentIntersect`, `WeldBoundary`, `WeldPolyline`, `SegmentsProperlyCross`, `EnsureCounterClockwise`, `RemoveSelfIntersections`, and a second anonymous namespace with `RayIntersect`)
**Purpose:** Implements the full node-solving algorithm declared in the header: polyline offsetting, pairwise arm-side collision with ray-cast fallback, corner arc filleting, boundary assembly, self-intersection removal, and winding normalization, plus ramp/gore/lane-connector helpers.
**Key API / responsibilities:**
- `WeldTolerance` (constexpr 10.0): points nearer than this are treated as coincident, guarding against zero-length edges/NaN normals.
- `SegmentIntersect`/`Cross2D`/`LeftNormal`: core 2D geometry primitives — `LeftNormal` rotates 90° CCW to give the left normal of a travel direction.
- `SegmentsProperlyCross`: strict interior-crossing test (shared endpoints don't count) via signed-area side tests on both segments.
- `EnsureCounterClockwise`: computes the shoelace signed area of the boundary and reverses it in place if negative; documents that `RoadMesh::AppendPrism` builds the junction slab "inside-out, top face pointing down" if handed a clockwise boundary, and that CCW angular arm ordering does not by itself guarantee a CCW final boundary once trims grow large relative to node size.
- `RemoveSelfIntersections`: standard 2-opt "uncrossing" pass — repeatedly finds any two non-adjacent boundary edges that properly cross and reverses the vertex run between them (swap-based in-place reversal), bounded by `SafetyIterations = NumVerts² + 16`; changes only edge order between existing vertices, never moves/drops a vertex.
- `PolylineLength`, `PointAtDistance`, `DirectionAtDistance`, `ProjectOntoPolyline`: straightforward polyline walks/interpolation; `DirectionAtDistance` falls back to `FVector2D(1,0)` for degenerate (<2 point) polylines or near-zero direction.
- `OffsetPolyline`: welds input first; for endpoints uses the outgoing/incoming normal directly; for interior points computes a bisector-based mitre (`MiterLength = Distance / CosHalf`), falling back to a bevel (two offset points instead of one) when `|MiterLength| > MaxMiterLength = |Distance| * Max(1.0, MaxMiterScale)`; welds the output before returning.
- `IntersectPolylines`: brute-force all-segment-pairs test between A and B, keeping the intersection with the largest distance travelled along A.
- `RayIntersect` (local): unbounded ray-vs-ray intersection used as a fallback when `IntersectPolylines` finds nothing within the sampled length — requires both `t` parameters ≥ 0 (forward on both rays); a negative `t` is treated as a genuine open gap (e.g. a T-junction's straight side), not a missed collision.
- `SolveNode`: (1) strips arms with `<2` centreline points or length `< WeldTolerance`; returns invalid solution if `<2` arms remain. (2) Computes each arm's `AngleRad` from its initial direction and sorts arms CCW by it. (3) Builds `LeftSides`/`RightSides` offset polylines per arm at `±HalfWidth`. (4) For each adjacent pair `(i, i+1 mod N)`, collides arm i's left side against arm i+1's right side via `IntersectPolylines`; on failure, tries the `RayIntersect` fallback from each side's own end tangent — if that also fails, the arms are genuinely diverging (open gap, skip); if it converges beyond the sampled length, bevels at 90% along each side (`PointAtDistance(..., BaseLen*0.9)`) rather than chasing the true (possibly far-off) mitre point, records `CornerRadii[i]=0.0`, and classifies ramp status via `IsRampConnection` even in the bevel branch (explicitly called out as "the common case," not an edge case). (5) On a successful bounded collision, computes the tangent-arc fillet: `HalfAngle` from the dot product of the two collision-side directions, `Radius = Min(BaseCornerRadius, MaxTangent * TanHalf)` where `BaseCornerRadius` is `Options.CornerRadius` or `× RampCornerRadiusMultiplier` for ramp corners, `MaxTangent = Min(AvailableA, AvailableB) * 0.9`; builds `Options.ArcSegments`-segment arc around a centre offset along the bisector; if radius/tangent distance too small, corner stays a sharp point (single vertex = the raw collision point). (6) Updates each arm's `TrimDistance` to the max of what either neighbouring corner demands. (7) Applies an unconstrained-arm floor: any arm no neighbour collided with gets `TrimDistance = Max(TrimDistance, WidestHalf)` (half the widest arm's HalfWidth in the whole node) so it doesn't trim to nothing — explicitly only applied to unconstrained arms, since applying it universally "overrode the collision results and made a wide road meeting a narrow one trim as if both were wide." All trims are then clamped to `[0, Available*0.9]`. (8) Computes cap points (`CapRight`/`CapLeft`) per arm at the final `TrimDistance`. (9) Re-anchors any corner arc that no longer lands exactly on its arm's final caps (within `WeldTolerance²×4`) — replacing it with a straight `{CapLeft[i], CapRight[Next]}` bevel — because an arm's final trim is the max across both its neighbours, so a corner arc built from only its own local collision can go stale when the OTHER neighbour forced a larger trim. (10) Walks arms in known CCW order building `Boundary` (right cap, left cap, corner arc vertices with `ArcAlpha` per vertex) and parallel `RoadsideChains` per corner (from left cap through arc to next arm's right cap, excluding the arm caps themselves). (11) Runs `RemoveSelfIntersections`, then `EnsureCounterClockwise` (order matters: 2-opt can flip orientation), then `WeldBoundary`, then drops a duplicate closing vertex if first/last are coincident; `bValid = Boundary.Num() >= 3`.
- `IsRampConnection`: `Abs(AngleGapRadians) < RampAngleThresholdRadians && ArmDrivingLanes != OtherDrivingLanes`.
- `FindGoreApex`: offsets both arms' centrelines at `DrivingHalfWidth` (A left, B right — noting these edges face each other since gore point is a driving-edge convergence), tries `IntersectPolylines`, falls back to the same `RayIntersect` technique as `SolveNode`'s corner collision.
- `MapLaneConnections`: `OutArmAToArmB[i] = i` for `i < ArmBLaneCount`, else `INDEX_NONE`.
- `BuildLaneConnectorCentreline`: computes each lane's lateral offset within its arm (`LaneWidth = DrivingHalfWidth*2/LaneCount`, lane 0 nearest the corner-facing edge — ArmA's Left side, ArmB's Right side, matching `SolveNode`'s wedge convention), builds start/end position+tangent (start tangent = `-DirOnA` since approaching the node is opposite the arm's own outward-pointing centreline direction; end tangent = `DirOnB` directly), and cubic-Hermite interpolates X and Y independently across `NumSegments`.
**Dependencies:** `RoadNetworkSolver.h`, `Algo/Reverse.h` (for `Algo::Reverse` used in `EnsureCounterClockwise`). Pure math — no engine actor/component types touched.
**Notable implementation details:** Two distinct "unbounded convergence" fallbacks (`SolveNode`'s corner collision and `FindGoreApex`) both use the same `RayIntersect` helper and the same reasoning: a shallow angle between arms makes the true offset-edge convergence point grow without bound (`HalfWidth / tan(halfAngle)`), so a fixed sample length can miss it entirely; the fix is either an unbounded ray cast (when forward-converging) or a bevel fallback (when the ray-cast convergence is real but too far beyond the sampled arm to use directly). The stale-corner-arc re-anchoring step (step 9 above) is called out as specifically triggered by clusters of arms only a few degrees apart, where one pair's mutual trim forces an arm's cap far back from where its OTHER corner's arc was originally anchored.

**Dependencies:** `DynamicMesh/DynamicMesh3.h`, `DynamicMesh/DynamicMeshAttributeSet.h`, `IndexTypes.h`, `CompGeom/PolygonTriangulation.h` (UE geometry-core), `GameFramework/Actor.h`, `Engine/World.h`, `CollisionQueryParams.h`, `Kismet/GameplayStatics.h`, `Core/GRTManager.h`, and directly includes the third-party `CDT.h` header from `Plugins/RoadBuilder-master/Source/ThirdParty/CDT/include/CDT.h` (with `#pragma warning(disable:4456)` and a local `M_PI` fallback define around that include).

### Source/RealtimeTerrain/Private/RoadSpiral.cpp

- `EvaluateHeight` — returns `0.0` for zero keys, `Keys[0].Height` for one key; otherwise finds the bracketing index via `RoadCurveGraph::FindElementIndex`, clamps it so `Index+1` is valid, guards a near-zero `SegmentLength` by returning `Start.Height` directly, and otherwise calls `FMath::CubicInterp(Start.Height, Start.Slope*SegmentLength, End.Height, End.Slope*SegmentLength, S/SegmentLength)`.

**Notable implementation details:** The `SegmentLength <= UE_DOUBLE_SMALL_NUMBER` guard in `EvaluateHeight` is explicitly there to prevent a 0/0 (or near-0 divisor) NaN height that would silently discard every triangle touching that vertex with no error — described in-code as "the exact failure mode `RebuildMesh`'s own height sanitization exists to catch elsewhere."

**Notable implementation details:** The hairpin test is a documented regression test for a real bug: the corner-fitting loop's overshoot-recovery branch divides by `Cos(Diff/2)`, which approaches 0 as the turn angle Diff approaches ±PI; a 179.99-degree turn is deliberately chosen just short of the fully-degenerate 180-degree case that `BuildSpiralCentreline` already skips via its own `Dir.IsNearlyZero()` check.
