## C++ files

### Plugins/GRT/Source/GRT/Public/Core/GRTManager.h
**Class/struct(s):** `AGRTManager` (primary UCLASS); `FGRTGPUStats`, `FGRTLandscapeMigrationOptions`, `FGRTGeoTIFFImportOptions`, `FGRTPadStamp` (USTRUCTs); `EGRTWorldMode` (UENUM); plain structs `FGRTChunkSnapshot`, `FGRTUndoEntry`.
**Purpose:** Declares the single per-world root actor that owns GRT's chunked terrain — streaming/loading chunks, replicating world configuration to clients, and exposing the full runtime API other systems and the editor UI call into: raster/GeoTIFF import, tiled offline Cesium import, sculpt/noise brushes, building/road pad integration, population, save/load, and world presets.
**Key API / responsibilities:**
- `MarkWorldModeChosen()` / `OnWorldModeChosen` / `bAwaitingWorldModeChoice` — the "world mode choice" bootstrap gate: `bAwaitingWorldModeChoice` defaults `true` (documented as necessary because other actors' `BeginPlay` order relative to this one isn't guaranteed) and is what actually suppresses Tick-driven chunk streaming, not `BeginPlay` itself.
- `ImportRasterLayer` / `UnloadRasterLayer` / `UnloadAllRasterLayers` / `LoadRasterLayersIntoScene` / `DynamicRasterLayers` + `AddDynamicRasterLayer`/`RemoveDynamicRasterLayer`/`LoadDynamicRasterLayer`/`UnloadDynamicRasterLayer` — multi-layer raster import pipeline: elevation must be imported first and every later layer must match its grid (size/scale/CRS/origin), header-only validation up front with pixel decode deferred to `LoadRasterLayersIntoScene`.
- `ImportCesiumTerrainTileset` / `ImportCesiumImageryOverlay` / `SetCutOutBackdropForTiledImport` / `SetTiledCesiumHeightOffset` — offline (`file:///`) Cesium quantized-mesh/XYZ-imagery pyramid display alongside GRT's own chunks; both refuse to run in Sandbox worlds; imagery overlay explicitly requests `{reverseY}` not `{y}` since local XYZ pyramids are row-0-at-north while Cesium's `{y}` means TMS (row-0-at-south).
- `ApplyGlobalBrush` / `ApplyGlobalNoise` / `Multicast_ApplyBrush` / `Multicast_ApplyGlobalNoise` — server-applies-then-multicasts sculpt editing.
- `RegisterBuilding`/`UnregisterBuilding`, `RefreshBuildingPads`/`RefreshBuildingPadsForChunk`, `SetExternalPadStamps`/`ClearExternalPadStamps`/`GetExternalPadBounds` — non-destructive pad-layer flattening shared by buildings (one footprint each) and non-building actors like roads (many small stamped quads along their length), composed per-chunk by whichever stamp wants the ground flattest.
- `Multicast_SyncChunkSculpt` — documented as sending sparse `(index,value)` pairs in batches rather than a full sculpt buffer, because a full 128-resolution buffer (65,536 bytes) overflows Unreal's 65,536-byte max RPC bunch size and is silently dropped.
- `SaveWorld`/`LoadWorld`/`SaveWorldToFile`/`LoadWorldFromFile`, `BuildSaveGameInstance`/`ApplyLoadedSaveGame` — persistence, both to the engine's named `SaveGame` slot system and to an explicit file path.
- `RegisterPersistentActor`/`PlacePersistentActorFromDescriptor`/`PlacePersistentActor`/`HarvestPersistentPopulation`/`SetPersistentPopulationDestroyed` — persistent population registry, GUID-keyed.
- `ImportFromLandscape`/`ImportFromLandscapeWithOptions`/`ImportInternal` (WITH_EDITOR only) — editor-time Landscape→chunk migration.
- `GetChunkAtLocation`, `GetChunksInRadius`, `GetChunksInBoxXY`, `GetNaturalTerrainHeightAtXY`, `CanBuildAtLocation`, `GetAISpawnZonesAtLocation`, `GetPCGSeedPointsForChunk` — spatial/gameplay query surface.
**Dependencies:** `IO/GRTRasterLayers.h`, `GameFramework/Actor.h`, `Core/GRTWorldTypes.h`, `World/GRTTileData.h`, `Core/GRTSaveGame.h`; forward-declares `AGRTChunk`, `ALandscapeProxy`, `ULandscapeComponent`, `UMaterialInterface`, `UGRTWorldPreset`, `AGRTEditController`, `FGRTGeoTIFFHeightSource`, and Cesium plugin types `ACesium3DTileset`, `UCesiumUrlTemplateRasterOverlay`, `ACesiumCartographicPolygon`.
**Notable implementation details:** Declares an explicit destructor and an `AGRTManager(FVTableHelper&)` constructor specifically so neither the compiler nor UHT's generated vtable-helper constructor tries to instantiate `TUniquePtr<FGRTGeoTIFFHeightSource>`'s destructor against the incomplete forward-declared type — both are defined in the .cpp where the type is complete.

### Plugins/GRT/Source/GRT/Private/Core/GRTManager.cpp
**Class/struct(s):** `AGRTManager` (implements a subset of the class — see below).
**Purpose:** Implements chunk streaming/lifecycle, per-frame LOD, sculpt brush/noise application, building/road pad refresh, replication callbacks, and world-framework bookkeeping (procedural chunk state, biome resolution, chunk seeding) for `AGRTManager`. Per `GRTManagerInternal.h`'s own comment ("When the population code moved to its own TU..."), this is only one of several translation units backing the class: raster/GeoTIFF import, tiled Cesium import, save/load, most of the population spawn/lifecycle (`RefreshPopulationForLoadedChunks`, `SyncPopulationForChunk`, `DespawnPopulationForChunk`, `TickPopulationState`, `SpawnPopulationActor`, etc.), stroke undo/redo (`BeginStroke`/`CommitStroke`/`Undo`/`Redo`), and editor Landscape migration are all declared in the header but **not defined in this file** — this file only calls forward into them.
**Key API / responsibilities:**
- `BeginPlay()` — resolves world-mode bootstrap in priority order: resume-from-save (GeoTIFF re-decode with `bClearExistingChunks=false`/`bEstablishGeoreferenceOrigin=false`) → pre-configured import with choice-screen disabled → pre-configured sandbox with choice-screen disabled → otherwise leaves `bAwaitingWorldModeChoice` at its default `true`.
- `Tick()` — every ~0.25s gathers all player-controller camera/pawn positions, runs `UpdateStreaming` (server only), then updates LOD on every chunk using each chunk's *nearest* player position; also drives `TickPopulationState(0.25f)` on a separate authority-only timer.
- `LoadMaterials()` — loads `MasterMaterial`/`HeightBrushMaterial` from `UGRTSettings` soft paths, falling back to `/Engine/BasicShapes/BasicShapeMaterial` if the settings path fails to resolve.
- `SetupLighting()` — early-returns if a `ADirectionalLight` already exists in the world; otherwise spawns one directional light + one movable sky light with real-time capture.
- `StartSandboxMode()` / `StartDEMImportMode()` / `MarkWorldModeChosen()` — the explicit mode-choice entry points; `StartDEMImportMode` destroys every existing `AGRTChunk` actor and resets all streaming queues; `MarkWorldModeChosen` zeroes `LastStreamingHash` to force an immediate streaming rescan and broadcasts `OnWorldModeChosen` only after clearing the flag.
- `ApplyGlobalBrush`/`ApplyGlobalNoise` + `Multicast_ApplyBrush_Implementation`/`Multicast_ApplyGlobalNoise_Implementation` — apply-locally-then-multicast-to-non-authority pattern; noise is Perlin-based, normalized by chunk `ZScale`, offset by `Seed*1337` per axis.
- `RegisterBuilding`/`UnregisterBuilding`, `RefreshBuildingPads`/`RefreshBuildingPadsForChunk`, `SetExternalPadStamps`/`ClearExternalPadStamps`/`GetExternalPadBounds` — gathers overlapping buildings and external (e.g. road) pad stamps per-chunk before touching anything (so the common no-overlap case costs one bounds test), then `ClearBuildingPad`/`StampBuildingPad` per contributor and `RecomputeHeightFromLayers`/`NotifyHeightBufferChanged`/`MarkLayerWeightsDirty`.
- `RegisterChunk`/`UnregisterChunk`/`GetChunkAtCoord`/`GetChunksInRadius`/`GetChunksInBoxXY`/`GetChunkBoundsXY` — chunk registry and spatial queries against `ActiveChunkMap`.
- `ShouldAllowChunkCoord`/`GetDistanceFromAuthoredChunks` — gates whether a coordinate may spawn: for `ImportedGeoTIFF` origin, only imported coords with a valid height source; for procedural, authored coords always allowed, else infinite-edge-growth or `GridExtent`-bounded when nothing is authored yet, else Manhattan-distance-bounded outskirts growth when `bEnableSeededOutskirts`.
- `EnsureChunkFrameworkState`/`ResolveBiomeForChunk` — creates/updates a `FGRTProceduralChunkState` per coordinate; biome resolution uses a `FRandomStream(MakeChunkSeed(Coord)).FRand()` gate against each `FGRTBiomeOverlay`'s noise-range and picks the highest-`Priority` match (ties won by later iteration since `>=`).
- `SendChunkSculptSync`/`Multicast_SyncChunkSculpt_Implementation` — collects only non-zero sculpt entries, batches at 3000 index/value pairs (~24KB) per multicast to stay under the 65,536-byte bunch limit.
- `UpdateStreaming`/`ProcessStreamingQueues` — hashes all players' chunk coordinates to skip rescanning when nobody has moved cells; builds a Manhattan-distance diamond load region (`ChunkLoadRadius`) and an unload set (`ChunkUnloadRadius`, skipped entirely while a GeoTIFF height source is resident); each tick processes unloads farthest-first then loads nearest-first, capped at `MaxChunkOpsPerTick` (or a fixed 16 during active DEM load backlog).
**Dependencies:** `Core/GRTSubsystem.h`, `Core/GRTEditController.h`, `Core/GRTSaveGame.h`, `Core/GRTWorldPreset.h`, `Settings/GRTSettings.h`, `World/GRTChunk.h`, `World/GRTOrchestrator.h`, `Building/GRTBuildingActor.h`, `GRTModule.h`, `Kismet/GameplayStatics.h`, `Engine/DirectionalLight.h`/`SkyLight.h`, `Net/UnrealNetwork.h` (`DOREPLIFETIME`), `NavigationSystem.h` (`UNavigationSystemV1::AddDirtyArea`), `IO/GRTGeoTIFFHeightSource.h`, and `Core/GRTManagerInternal.h` for the shared geometry helpers (`MakeChunkBounds`, `MakeWorldTransform`, `ChunkIndexFromLocalAxis`).
**Notable implementation details:** `RegisterChunk` destroys a stale duplicate actor at the same coordinate only when that stale instance lacks authority (a client-side leftover), leaving an authoritative duplicate untouched; `UnregisterChunk` only removes an `ActiveChunkMap` entry if the currently-registered pointer for that coordinate is literally the actor being unregistered; `ApplyMaterialToActiveChunks`/`RegisterChunk`/`SpawnConfiguredChunk` all skip setting `MasterMaterial` when `WorldOriginKind == ImportedGeoTIFF`; `SpawnConfiguredChunk` uses `bDeferConstruction=true` then `FinishSpawning`, relying on the chunk's own `BeginPlay`→`RegisterChunk` call to populate `ActiveChunkMap`, falling back to doing it manually only if that didn't happen.

### Plugins/GRT/Source/GRT/Private/Core/GRTManagerInternal.h
**Class/struct(s):** none (free functions/data only) — a header-only `GRTWorldFramework` namespace of `inline` helper functions.
**Purpose:** Shares small pure-geometry helper functions across `AGRTManager`'s multiple translation units. Per the file's own comment, these were originally file-local statics in `GRTManager.cpp`; when the population code was split into its own TU it needed the same helpers, so they were promoted to a shared private header rather than duplicated.
**Key API / responsibilities:**
- `MakeChunkBounds(Manager, Coord, ChunkSize, ZExtent=4000.0f)` — returns a world-space `FBox::BuildAABB` centered at `Manager.GetActorLocation() + (Coord.X*ChunkSize, Coord.Y*ChunkSize, 0)` with half-extents `(ChunkSize/2, ChunkSize/2, ZExtent)`.
- `MakeWorldTransform(LocalTransform, ParentTransform)` — trivial `LocalTransform * ParentTransform`.
- `ChunkIndexFromLocalAxis(LocalAxis, ChunkSize)` — `Floor((LocalAxis + ChunkSize*0.5f) / ChunkSize)`, returning `0` if `ChunkSize <= KINDA_SMALL_NUMBER` rather than dividing by a near-zero value.
**Dependencies:** `CoreMinimal.h`, `Core/GRTManager.h`.
**Notable implementation details:** Functions are declared `inline`, not `static`, specifically so every including TU shares one definition instead of each getting its own private copy — a deliberate choice tied to the class being implemented across multiple .cpp files.

### Plugins/GRT/Source/GRT/Public/Core/GRTSubsystem.h
**Class/struct(s):** `UGRTSubsystem : public UWorldSubsystem`.
**Purpose:** Per-world lifecycle registry that caches the active `AGRTManager` for O(1) global lookup, and a designated hook for flushing background IO safely before world teardown/level transitions.
**Key API / responsibilities:**
- `Initialize`/`Deinitialize` — `UWorldSubsystem` lifecycle overrides.
- `RegisterManager(AGRTManager*)` / `UnregisterManager(AGRTManager*)` — called by `AGRTManager::BeginPlay`/`EndPlay`; header states registration "Validates only one manager exists per world."
- `GetTerrainManager() const` (`BlueprintPure`) — returns the currently active manager, or `nullptr` if the world has none.
- `FlushPendingTasks()` (`BlueprintCallable`) — documented as waiting for all pending async save tasks to complete, "crucial to call before level transitions to prevent data corruption."
- private `TWeakObjectPtr<AGRTManager> ActiveManager` (`Transient`) — weak specifically so the subsystem doesn't keep the actor alive if the level unloads violently.
**Dependencies:** `Subsystems/WorldSubsystem.h`; forward-declares `AGRTManager`.

### Plugins/GRT/Source/GRT/Private/Core/GRTSubsystem.cpp
**Class/struct(s):** `UGRTSubsystem`.
**Purpose:** Implements the manager registry described in the header, plus a one-time world-settings fix applied in `Initialize()` that disables `AWorldSettings::bEnableWorldBoundsChecks` to prevent Cesium's origin-rebasing from spuriously killing/respawning an airborne pawn.
**Key API / responsibilities:**
- `Initialize()` — calls `Super::Initialize`, then sets `GetWorld()->GetWorldSettings()->bEnableWorldBoundsChecks = false`. The comment explains: Cesium's world-origin rebasing shifts every actor's absolute Z as the camera moves real-world distances, and `KillZ` is a fixed absolute threshold, so a rebase can make a legitimately airborne pawn read as "fallen below KillZ" and get destroyed/respawned — mistaken for the camera "bouncing back" mid-flight. States this isn't project-specific (CesiumRuntime itself logs a warning recommending the same fix) and is done here, in world-subsystem `Initialize` (which runs before any actor's `BeginPlay`), rather than relying on the level's saved `WorldSettings` checkbox, so it can't silently regress.
- `Deinitialize()` — calls `FlushPendingTasks()`, resets `ActiveManager`, logs, then `Super::Deinitialize()`.
- `RegisterManager(InManager)` — no-ops on null; if a *different* manager is already registered, logs a `Warning` ("Multiple Managers detected! Overwriting registration to %s") but still overwrites `ActiveManager` unconditionally.
- `UnregisterManager(InManager)` — resets `ActiveManager` only if it currently points at `InManager`.
- `GetTerrainManager() const` — returns `ActiveManager.Get()` if `IsValid()`, else `nullptr`.
- `FlushPendingTasks()` — current body is a no-op; comments describe intended future use of `FTaskGraphInterface::Get().WaitUntilTaskCompletes(...)` against a tracked handle, but no such tracking exists yet.
**Dependencies:** `Core/GRTManager.h`, `Engine/World.h`, `GameFramework/WorldSettings.h`, `Async/TaskGraphInterfaces.h` (included but unused — no actual task graph call is made).
**Notable implementation details:** `FlushPendingTasks` is a documented placeholder — despite the header calling it "crucial to call before level transitions," it currently performs no synchronization at all.

### Plugins/GRT/Source/GRT/Public/Core/GRTEditGameMode.h
**Class/struct(s):** `AGRTEditGameMode : public AGameModeBase`.
**Purpose:** Configures the default pawn/controller classes so a terrain-editing session gets the pinned-camera edit input scheme (left-drag sculpts, right-drag orbits) from the first frame, and overrides default-pawn spawning so multiple players sharing one `PlayerStart` don't collide.
**Key API / responsibilities:**
- Constructor sets `DefaultPawnClass`/`PlayerControllerClass` (implemented in the .cpp).
- `SpawnDefaultPawnAtTransform_Implementation` override — header comment explains the map ships a single `PlayerStart`, so every player would otherwise spawn co-located; default collision handling refuses to place a second pawn inside the first, leaving player 2 with a controller but no pawn (no camera, no cursor trace, no sculpting). This override forces the spawn through and fans players out.
- private `int32 SpawnedPawnCount` — tracks pawns spawned so far, used only for the fan-out offset.
**Dependencies:** `GameFramework/GameModeBase.h`.

### Plugins/GRT/Source/GRT/Private/Core/GRTEditGameMode.cpp
**Class/struct(s):** `AGRTEditGameMode`.
**Purpose:** Implements the pawn/controller class wiring and the collision-safe multi-player spawn described in the header.
**Key API / responsibilities:**
- Constructor — `DefaultPawnClass = AGRTEditPawn::StaticClass(); PlayerControllerClass = AGRTEditController::StaticClass();`.
- `SpawnDefaultPawnAtTransform_Implementation(NewPlayer, SpawnTransform)` — resolves the pawn class via `GetDefaultPawnClassForController(NewPlayer)`, returns `nullptr` immediately if there's no class or no `GetWorld()`; builds `FActorSpawnParameters` with `Instigator = GetInstigator()`, `ObjectFlags |= RF_Transient`, `SpawnCollisionHandlingOverride = ESpawnActorCollisionHandlingMethod::AlwaysSpawn`; offsets `SpawnTransform` along +X by `SpawnedPawnCount * 1500.0f` (first player unshifted, each subsequent one steps another 1500uu along X) then increments `SpawnedPawnCount`; spawns via `GetWorld()->SpawnActor<APawn>(...)`; logs a `Warning` naming the controller (or "null controller") if the spawn fails.
**Dependencies:** `Core/GRTEditPawn.h`, `Core/GRTEditController.h` (referenced only by class name, for `StaticClass()`).
**Notable implementation details:** The entire collision-avoidance mechanism is `AlwaysSpawn` collision override plus a fixed +1500uu-per-player offset along a single axis — there is no search for genuinely free space, so a third or later player is placed 3000uu/4500uu/etc. along X with no validation against terrain height or other actors at that offset.

### Plugins/GRT/Source/GRT/Private/Core/GRTManagerPopulation.cpp
**Class/struct(s):** none (member functions of `AGRTManager`, declared elsewhere)
**Purpose:** Implements `AGRTManager`'s persistent population registry — the system that tracks non-terrain world content (props, harvestables, procedural spawns) as data entries independent of their spawned actor, so they survive chunk streaming, harvesting/regrowth cycles, and save/load. Split out of a single 3,408-line `GRTManager.cpp` per the file's header comment, with no API change.
**Key API / responsibilities:**
- `MakeDescriptorFromActor` — builds an `FGRTPopulationDescriptor` from an existing actor (captures `StaticMesh`/`MaterialOverride` if it's an `AStaticMeshActor`).
- `RegisterPersistentActor` — authority-only; registers an already-placed actor into the registry (dedupes via `PopulationIdByActor`), computes `TerrainOffset` if `bSnapToTerrain`, stores a `LocalTransform` relative to the manager, broadcasts `"Registered"`, and calls `RefreshNavigationForBounds`.
- `PlacePersistentActorFromDescriptor` / `PlacePersistentActor` — authority-only; creates a new registry entry from a descriptor + world transform (optionally tagged with a `SourceRuleId` from a spawn rule) and immediately spawns the actor.
- `BindPopulationActor` — maps `PopulationId <-> AActor` both ways and hooks `AActor::OnDestroyed` to `HandlePopulationActorDestroyed`.
- `SpawnPopulationActor` — authority-only; resolves the entry's chunk, computes world transform (snapping Z to `Chunk->GetHeightAtLocation` + `TerrainOffset` if requested), spawns either the `ActorClass` or a fallback `AStaticMeshActor` wrapping `StaticMesh`, tags it `"GRTPersistent"` plus its `TypeId` and any descriptor `Tags`, and optionally attaches it to the chunk's root component.
- `SetPopulationStateInternal` — transitions an entry's `EGRTPopulationState` (Active/Regrowing/Harvested/Destroyed), computing `RemainingRegrowthTimeSeconds`, either syncing the chunk (Active) or destroying the live actor (any other state), then broadcasting and refreshing navigation.
- `HarvestPersistentPopulation` — picks Regrowing vs. Harvested depending on `bAllowRegrowth`/`RegrowthDelaySeconds`.
- `SetPersistentPopulationDestroyed` — toggles Destroyed/Active.
- `GeneratePopulationForChunk` — authority-only, gated on `ProceduralWorldSettings.bGeneratePopulationFromRules` and a per-chunk `bPopulationGenerated` flag; for each `FGRTPopulationSpawnRule` filters by authored/procedural chunk, `DistanceFromAuthored` range, and `RequiredBiomeTag`, then uses a deterministic `FRandomStream(MakeChunkSeed(Coord) ^ GetTypeHash(RuleId))` to pick an instance count and place points with up to 12 rejection-sampling attempts per instance against `Rule.MinSpacing`.
- `SyncPopulationForChunk` — ensures framework state, generates rule-based population, then spawns/repositions Active entries or destroys non-Active ones for a given chunk coordinate.
- `DespawnPopulationForChunk` — destroys all live actors for entries in a chunk (used when a chunk streams out) without touching the entry's state.
- `HandlePopulationActorDestroyed` — reacts to an externally-destroyed (not registry-initiated) actor by transitioning its entry to Regrowing or Harvested/Destroyed depending on `Kind`/regrowth settings; skips the transition entirely if the destroy was registry-initiated (tracked via `PopulationDestroyInProgress`).
- `TickPopulationState` — decrements `RemainingRegrowthTimeSeconds` for Regrowing entries, flips them back to Active on expiry, and re-syncs affected chunks.
- `RefreshPopulationForLoadedChunks` — re-syncs every currently active chunk.
- `BroadcastPopulationChanged` — fires `OnPopulationChanged` with an `FGRTPopulationChangeEvent`.
- `DestroyTrackedPopulationActors` — bulk-destroys every actor currently tracked and clears all population maps (used on world load/teardown).
**Dependencies:** `GRTManager.h`/`GRTManagerInternal.h` (own class + shared helpers like `GRTWorldFramework::MakeChunkBounds`/`MakeWorldTransform`), `GRTSubsystem.h`, `GRTSaveGame.h`, `GRTWorldPreset.h`, `Settings/GRTSettings.h`, `World/GRTChunk.h` (`GetHeightAtLocation`, `WorldSize`), `Kismet/GameplayStatics.h`, `Engine/StaticMeshActor.h`/`Components/StaticMeshComponent.h`, `NavigationSystem.h` (via `RefreshNavigationForBounds`), `Net/UnrealNetwork.h`.
**Notable implementation details:** Rule-based spawn placement is fully deterministic per chunk/rule via a seeded `FRandomStream`, so regenerating the same chunk reproduces the same layout. `PopulationDestroyInProgress` is the mechanism distinguishing a registry-initiated `Destroy()` from an external one (e.g., a player deleting the actor directly) so `HandlePopulationActorDestroyed` doesn't double-process registry-driven destructions. All mutating entry points are gated on `HasAuthority()`.

### Plugins/GRT/Source/GRT/Private/Core/GRTManagerLandscapeImport.cpp
**Class/struct(s):** none (member functions of `AGRTManager`); one file-local constant `MaxCapturedLandscapeLayerMappings = 4`
**Purpose:** Converts an authored `ALandscapeProxy` (heightmap, paint/weight layers, placed foliage) into GRT chunks. Entirely `WITH_EDITOR`-gated since Landscape editing and foliage APIs aren't available in packaged builds; this was, per the header comment, the cleanest concern to split out of the original manager file because the `#if WITH_EDITOR` fence already marked its boundary.
**Key API / responsibilities:**
- `ManualImport` / `MigrateLandscapeProject` — thin editor entry points calling `ImportFromLandscape`/`ImportFromLandscapeWithOptions` on `TargetLandscapeSource`.
- `ResampleLandscapeData` — pulls one `ULandscapeComponent`'s height data via `FLandscapeEditDataInterface::GetHeightDataFast`, normalizes `uint16` samples to `[0,1]` into `Chunk->BaseBuffer`, zeroes `SculptBuffer`/`DetailBuffer`/`HeightBuffer` and (per an inline comment) the pad-weight/pad-target buffers too since this path bypasses `Initialize()`, then calls `Chunk->RecomputeHeightFromLayers()` and `Chunk->RebuildPhysicsMesh()`.
- `ImportFromLandscape` / `ImportFromLandscapeWithOptions` — wrap `ImportInternal` with an `FGRTLandscapeMigrationOptions`.
- `ImportInternal` — the actual migration: optionally pauses streaming and clears existing chunks, resets `LandscapeMigrationState` and stamps `WorldOriginKind = ImportedLandscape`, derives `GlobalChunkSize` from `ComponentSizeQuads * LandscapeScale.X`, repositions the manager actor to sit centered under the landscape (`SourceLocation + half chunk size` in X/Y, `-256 * LandscapeScale.Z` in Z), optionally adopts the landscape's material as `MasterMaterial`, captures up to `MaxCapturedLandscapeLayerMappings` (4) distinct weightmap layer names into `LandscapeMigrationState.LayerMappings` (rest go to `UnmappedLayerNames`), then for each `ULandscapeComponent` spawns a chunk via `SpawnConfiguredChunk`, sets `ZScale = 512 * LandscapeScale.Z`, resamples height, and (if `bTransferPlacedFoliage`) captures placed foliage. Finishes with `RebuildChunkMap`, `ApplyMaterialToActiveChunks`, and optionally hides the source landscape.
- The `CapturePlacedFoliageForComponent` lambda — reads `AInstancedFoliageActor::GetInstancedFoliageActorForLevel`'s per-component instance map, splits it into `UFoliageType_InstancedStaticMesh` (mesh+override materials, deduped by a mesh-path+material-path definition key) and `UFoliageType_Actor` (actor class + attach-to-base flag, deduped similarly) buckets, converts each placement's world transform to a transform local to the chunk plus a terrain-relative Z offset, and hands the flattened arrays to `Chunk->SetTransferredFoliageData` / `Chunk->SetTransferredActorFoliageData`.
**Dependencies:** `GRTManager.h`/`GRTManagerInternal.h`, `GRTSubsystem.h`, `Settings/GRTSettings.h`, `World/GRTChunk.h`; editor-only: `LandscapeProxy.h`, `LandscapeComponent.h`, `LandscapeLayerInfoObject.h`, `LandscapeInfo.h`, `LandscapeEdit.h` (`FLandscapeEditDataInterface`), `LandscapeDataAccess.h`, `InstancedFoliageActor.h`, `FoliageType_Actor.h`, `FoliageType_InstancedStaticMesh.h`; `Kismet/GameplayStatics.h` for actor enumeration/destruction.
**Notable implementation details:** Landscape paint layers are captured only as metadata (`LandscapeMigrationState.LayerMappings`/`UnmappedLayerNames`) — the comment explicitly notes GRT no longer has paint layers to import them into. `ResampleLandscapeData` must zero the pad buffers alongside the terrain buffers because it resizes buffers directly rather than through `Initialize()`, or `RecomputeHeightFromLayers` would read stale pad data. Foliage definitions are deduplicated by a composite key (mesh path + per-slot override material paths, or actor class path + attach flag) so repeated placements of the same foliage type share one definition entry rather than one per instance.

### Plugins/GRT/Source/GRT/Private/Core/GRTManagerPersistence.cpp
**Class/struct(s):** none (member functions of `AGRTManager`)
**Purpose:** Handles moving world state to/from disk at two granularities: whole-world save/load (through `UGRTSaveGame`, either engine save-slots or an explicit file path) and single-chunk cache read/write (the zlib-compressed per-chunk cache the streamer uses when evicting/reloading dirty chunks).
**Key API / responsibilities:**
- `BuildSaveGameInstance` — assembles a `UGRTSaveGame` from current manager state: location, `GlobalChunkSize`, `LandscapeMigrationState`, `WorldOriginKind`, `GeoTIFFImportState`, `ProceduralWorldSettings`, `BiomeOverlays`, `PopulationSpawnRules`, `AISpawnZones`, `BuildPermissionZones`, `ProceduralChunkStates`, `PersistentPopulationEntries`, `ImportedChunkCoords`, the master material path (skipped if under `/Engine/Transient`), every registered building's `ToData()`, the model catalog and placed models, every active chunk's `GetSerializedData()`, and every chunk in this session's eviction cache that is not currently active (read back via `LoadChunkFromCache`) — so edits that streamed out are not lost from the save.
- `SaveWorld(SlotName)` / `LoadWorld(SlotName)` — engine `SaveGameToSlot`/`LoadGameFromSlot` with a default slot name `"GRTSave"`.
- `SaveWorldToFile` / `LoadWorldFromFile` — serialize via `SaveGameToMemory`/`LoadGameFromMemory` and read/write raw bytes with `FFileHelper`.

**Purpose:** Implements per-player sculpt-stroke undo/redo history. ### Plugins/GRT/Source/GRT/Private/Core/GRTProceduralGenerator.cpp
**Class/struct(s):** none (implements `FGRTProceduralGenerator` static methods; free functions `Fade`, `Lerp`, `Grad` plus a static 512-entry `PerlinPermutation` table)
**Purpose:** Implements classic (Ken Perlin style) gradient noise and fBm, then uses them to synthesize a chunk's base (macro) and detail (micro/erosion) height layers for Sandbox-mode procedural terrain.
**Key API / responsibilities:**
- `PerlinPermutation[512]` — the standard doubled 256-entry permutation table (hardcoded values), used for hashing lattice coordinates.
- `Fade(T)` — the quintic 6t⁵-15t⁴+10t³ smoothstep curve.
- `Lerp(T,A,B)` — linear interpolation.
- `Grad(Hash, X, Y)` — 2D gradient function: uses `Hash & 7` to pick one of 8 gradient directions, combining X/Y with sign flips from bits 0 and 1 of the hash (note the asymmetric weighting: the "V" component is doubled — `2.0f * V`).
- `PerlinNoise(X, Y)` — standard 2D Perlin: floors to lattice cell (`& 255` wrap), computes fade curves `U`/`V`, hashes the 4 corners via the permutation table, and bilinearly interpolates their gradient dot-products.
- `FractalNoise(X, Y, Octaves, Persistence)` — sums `PerlinNoise` across octaves with frequency doubling (`Frequency *= 2.0f`) and amplitude decay (`Amplitude *= Persistence`), normalizing by the accumulated `MaxValue` (returns 0 if `MaxValue <= 0`).
- `GenerateSandboxHeights(...)` — for every vertex in a `Resolution × Resolution` grid: computes world X/Y from `GridCoord * WorldSize` plus a `[-0.5, 0.5] * WorldSize` offset across the chunk; the **Base** layer runs `FractalNoise` at `0.0005` frequency scale with 4 octaves/0.45 persistence, remaps into `[ProceduralFloor, ProceduralFloor+ProceduralRelief]`, then clamps to `[0,1]`; the **Detail** layer runs `FractalNoise` at `0.0015` scale with 2 octaves (default persistence 0.5) scaled by `0.02f`, unclamped. Buffers are sized via `SetNumUninitialized` before filling.
**Dependencies:** Only `Core/GRTProceduralGenerator.h` (`FMath::FloorToInt`, `FMath::FloorToFloat`, `FMath::Clamp` from Core).
**Notable implementation details:** World-space coordinates are computed in `double` (`WorldX`/`WorldY`) before being narrowed to `float` for the noise calls — precision matters at chunk-grid scale but the noise functions themselves work in float. The permutation table appears twice in the same 512-entry array (indices 0-255 and 256-511 are identical), which is the standard trick to avoid a second modulo when indexing `A+1`/`B+1`.

**Purpose:** The runtime-generated modular building actor: a closed footprint spline drives procedural placement of wall panels, corner posts, and floor/roof slabs from a `UGRTBuildingKit`, fully replicated for multiplayer and integrated with GRT's terrain-pad flattening system.
**Key API / responsibilities:**
- Components: `SceneRoot`, `FootprintSpline` (`USplineComponent`).
- Replicated config: `FloorCount` (ClampMin 1, UIMax 20, `OnRep_FloorCount`), `Kit` (`OnRep_Kit`), `bGenerateWalls`/`bGenerateFloors`/`bGenerateRoof`/`bGenerateCornerPosts`/`DoorSegmentIndex` (all `OnRep_BuildingConfig`), `BuildingId` (Replicated), `ReplicatedSplinePoints` (`OnRep_SplinePoints`).
- `ReplicatedScale3D` (`OnRep_Scale3D`) — header comment explains this exists because `FRepMovement` (driven by `SetReplicateMovement`) has no `Scale3D` field, so without explicit replication a gizmo Scale-mode drag would only resize the building on the machine that performed the drag.
- Terrain pad properties: `bFlattenTerrain`, `bAutoPadHeight`, `PadTargetWorldZ` (EditCondition `!bAutoPadHeight`), `PadFalloff` (ClampMin 0, UIMax 2000) — all `OnRep_PadSettings`.
- `bIsHolographicPreview` (Transient) + `SetIsHolographicPreview(bool)`/`ApplyHolographicVisuals()` — ghost/preview mode with no collision, no pad stamping.
- `ResolvePadTargetWorldZ()` — BlueprintCallable; resolves the actual flatten height, documented as caching the auto-sampled height until the building changes because chunk data availability varies as terrain streams.
- `RelevelToTerrain()`, `SnapToPadHeight()` — CallInEditor terrain-pad utilities.
- `NotifyBuildingChanged()` — BlueprintCallable; header comment says call after any transform/footprint/pad-setting change; on authority also resyncs `ReplicatedScale3D`.
- `RegenerateBuilding()`, `ResetToDefaultFootprint()`, `SetFloorCount(int32)` — CallInEditor / BlueprintCallable generation entry points.
- `GetBuildingHeight()` (BlueprintPure), `GetFootprintPolygonLocal()`, `GetFootprintPolygonWorld()`, `GetFootprintBoundsWorld(float Padding=0)`.
- `SyncSplinePointsToReplication()`, `GatherSplinePointsLocal()`, `SetSplinePointLocal(int32, FVector, bool bUpdatePad=true)`, `SetSplinePoints(TArray<FVector>&)`, `AddSplinePoint()`, `RemoveSplinePoint(int32=INDEX_NONE)`, `EnforceLinearTangents()`.
- `ToData()` / `ApplyData(const FGRTBuildingData&, bool bRegenerate=true)` — serialization round-trip, covering transform with scale, footprint, floors, kit (an empty path clears it, since undo rewinds live buildings through here), and pad settings. `ApplyData` also resyncs `ReplicatedSplinePoints`, without which clients kept the constructor's default rectangle.
- `static SpawnFromData(UWorld*, const FGRTBuildingData&)` — deferred spawn with pad settings written before `FinishSpawning`, then `ApplyData`; the one restore path for save-game load and undo, so a non-flattening building never stamps a pad during its own spawn.
- Protected lifecycle: `OnConstruction`, `BeginPlay`, `EndPlay`, `PostNetReceiveLocationAndRotation`, six `OnRep_*` UFUNCTIONs, and `WITH_EDITOR`-gated `PostEditChangeProperty`/`PostEditMove`.
- Private: `FPanelPlacement` struct (`Width`, `Offset`), `Instancers` (Transient array of `UInstancedStaticMeshComponent*`), `bSuppressRegenerate`, `LastPadBoundsWorld`, `CachedPadTargetWorldZ`/`bPadTargetCached` (mutable), `FindManager()`, `TraceGroundHeightAtXY()` (documented as a fallback for ground with no GRT chunk, e.g. imported Cesium tiles — mirrors `RoadMesh::SampleGroundHeight`'s identical fallback), `ResolveKit()`, `GetOrCreateInstancer()`, `ClearAllInstances()`, `PlanSegmentPanels()`, `BuildWalls()`, `BuildCornerPosts()`, `BuildSlabs()`, `PlaceSlabCell()`, `IsCellInsidePolygon()`, `IsPointInPolygon()`.
**Dependencies:** `GameFramework/Actor.h`, `Building/GRTBuildingTypes.h` (for `FGRTBuildingData`); forward-declares `USplineComponent`, `UInstancedStaticMeshComponent`, `UStaticMesh`, `UGRTBuildingKit`.
**Notable implementation details:** Class comment states the footprint spline is treated strictly as a polyline (every point forced to linear tangents) because the panel kit is flat modular pieces that can't follow a curve; geometry is pooled into one `UInstancedStaticMeshComponent` per unique mesh so a large building costs few draw calls.

### Plugins/GRT/Source/GRT/Private/Building/GRTBuildingActor.cpp
**Class/struct(s):** none (implementation of `AGRTBuildingActor`)
**Purpose:** Full procedural generation pipeline for a spline-footprint building — wall-panel layout (greedy width fill), corner posts, subdividing floor/roof slab tiling — plus multiplayer replication plumbing and terrain-pad height resolution/stamping.
**Key API / responsibilities:**
- Constructor: `bReplicates=true`, `bAlwaysRelevant=true`, `SetReplicateMovement(true)`; seeds a default 1200x800 rectangle (constants `DefaultFootprintX=1200`, `DefaultFootprintY=800`, both exact multiples of the 400uu module) since a stock `USplineComponent` starts as a 2-point line; assigns a new `BuildingId` GUID; syncs replication array; sets `ReplicatedScale3D = GetActorScale3D()`.
- `GetLifetimeReplicatedProps` — `DOREPLIFETIME` for all 14 replicated fields listed in the header.
- `SyncSplinePointsToReplication()` — copies local spline point locations into `ReplicatedSplinePoints`.
- `OnRep_FloorCount`/`OnRep_Kit`/`OnRep_BuildingConfig` — each calls `RegenerateBuilding()` then `NotifyBuildingChanged()`.
- `OnRep_PadSettings` — if `PadTargetWorldZ != 0`, snaps actor Z to it, then calls `NotifyBuildingChanged()`.
- `OnRep_SplinePoints` — rebuilds the spline from `ReplicatedSplinePoints` (only if ≥3 points), re-enforces linear tangents, regenerates, notifies.
- `OnRep_Scale3D` — calls `SetActorScale3D(ReplicatedScale3D)` then `NotifyBuildingChanged()` (no `RegenerateBuilding()` — comment explains geometry is generated once at local size and scaled uniformly by the actor transform like any other actor, so regeneration is unnecessary, matching `OnRep_PadSettings`'s pattern rather than the config-changing OnReps).
- `BeginPlay` — regenerates + notifies. `EndPlay` — calls `Manager->UnregisterBuilding(this)` unless the reason is `EndPlayInEditor`/`Quit`/`LevelTransition` (comment: no point recomputing ground during world teardown).
- `OnConstruction` — regenerate + notify.
- `WITH_EDITOR`: `PostEditChangeProperty` regenerates+notifies; `PostEditMove(bFinished)` regenerates every frame during drag (cheap, instance-transform only) but defers `NotifyBuildingChanged()` (pad refresh, expensive) until `bFinished`.
- `FindManager()` — via `UGRTSubsystem::GetTerrainManager()`, falling back to `GetActorOfClass` scan.
- `PostNetReceiveLocationAndRotation` — calls `NotifyBuildingChanged()`.
- `RelevelToTerrain()` — invalidates the pad-height cache and notifies.
- `ResolvePadTargetWorldZ()` — non-authority clients return `PadTargetWorldZ` (or actor Z if unset); authority: returns `PadTargetWorldZ` directly if `!bAutoPadHeight`; else returns the cache if valid; else samples the footprint polygon's corners, edge midpoints, and centroid via `Manager->GetNaturalTerrainHeightAtXY`, falling back per-sample to `TraceGroundHeightAtXY` when no chunk covers that XY; takes the **maximum** ground height across all successful samples (falling back to the average only if `MaxGroundZ` stayed at `-MAX_FLT`, i.e. never true given the sample-count guard) so the building sits fully above peaks/ridges/slopes; caches into `CachedPadTargetWorldZ`/`bPadTargetCached`. A long comment explains this function deliberately does NOT write back to the replicated `PadTargetWorldZ` — that used to happen via a `const_cast` but was removed because ordinary read-only callers (e.g. GRTManager's pad-stamping) shouldn't silently commit-and-replicate a value as a side effect of a query; only `SnapToPadHeight()` explicitly commits it.
- `TraceGroundHeightAtXY()` — vertical line trace from +200km to -200km on `ECC_WorldStatic`, ignoring self.
- `SnapToPadHeight()` — invalidates cache, resolves target Z, moves actor to it, commits `PadTargetWorldZ`, notifies.
- `SetIsHolographicPreview(bool)` — when enabling: disables terrain flatten, collision, replication, damage; unregisters from the manager. Always calls `ApplyHolographicVisuals()`.
- `ApplyHolographicVisuals()` — loads `/Game/SD_Art/Industrial_Architecture/Materials/MI_Window_Glass` (fallback to `BasicShapeMaterial`), disables collision/shadow on every instancer, and overrides every material slot.
- `NotifyBuildingChanged()` — early-returns for holographic previews; on authority resyncs `ReplicatedScale3D` from the real current scale; finds the manager (returns if none); calls `Manager->RegisterBuilding(this)`; invalidates the pad cache; computes `CurrentBounds = GetFootprintBoundsWorld(PadFalloff)`; unions with `LastPadBoundsWorld` (so chunks the building just vacated get natural ground restored in the same pass that stamps its new location); updates `LastPadBoundsWorld`; calls `Manager->RefreshBuildingPads(Area)`.
- `ResolveKit()` — returns `Kit` if set, else `GetDefault<UGRTBuildingKit>()` (the class-default CDO, chosen specifically so unconfigured buildings don't carry a private kit subobject into the save).
- Footprint editing: `ResetToDefaultFootprint()` (rebuilds the default rectangle, counter-clockwise winding, suppressing regen mid-edit via `bSuppressRegenerate`), `SetSplinePointLocal()`, `SetSplinePoints()`, `AddSplinePoint()` (inserts a midpoint between last and first point, offset by `+200` in X), `RemoveSplinePoint()` (refuses to go below 3 points), `EnforceLinearTangents()` (forces every point to `ESplinePointType::Linear`).
- `GatherSplinePointsLocal()`, `GetFootprintPolygonLocal()`, `GetFootprintPolygonWorld()` (transforms local XY through `GetActorTransform()`), `GetFootprintBoundsWorld(Padding)`.
- `GetBuildingHeight()` — `FloorHeight * max(FloorCount,0)`.
- `SetFloorCount(int32)` — clamps to min 1, regenerates if changed.
- `GetOrCreateInstancer(Mesh)` — pools by exact mesh match; sets `Movable` mobility **before** registration (comment: otherwise moving the building warns about relocating a "static" component every drag).
- `ClearAllInstances()` — clears every pooled ISM's instances (doesn't destroy the components).
- `RegenerateBuilding()` — respects `bSuppressRegenerate`; clears instances; resolves kit and bails with a `LogGRT` Warning if `!ActiveKit->IsUsable()`; enforces linear tangents; gathers points (bails if `<2`); conditionally calls `BuildWalls`, `BuildCornerPosts`, `BuildSlabs`; re-applies holographic visuals if in preview mode.
- `PlanSegmentPanels(SegmentLength, Kit)` — greedy largest-first fill: repeatedly picks the largest panel width `≤ Remaining + PlacementTolerance(1.0uu)` from `GetPanelWidthsDescending()`, appending `{Width, Offset}` and advancing offset/remaining; if `Remaining` leaves a stub shorter than the smallest panel width, it appends one more panel of the smallest width placed **flush with the far end** of the segment (`SegmentLength - Smallest`), deliberately overlapping the previous panel rather than leaving a gap — comment notes footprint grid snap (a separate, not-shown-here phase 5 feature) normally prevents this from firing.
- `BuildWalls(Points, Kit)` — for each segment (closed loop wraps `NumPoints`), computes direction/length, skips near-zero-length segments; computes panel yaw as `atan2(Dir.Y,Dir.X) + Kit->SegmentYawOffset`; calls `PlanSegmentPanels`; for each floor and each planned panel, decides whether to place the door mesh (only floor 0, matching `DoorSegmentIndex`, not already placed on this segment, and only if the planned width exactly equals `DoorWidth = round(Kit->ModuleWidth)`) or the regular panel via `ResolvePanelOfWidth`; falls back to engine cube; if using the basic cube fallback mesh, computes a stretched box transform instead of the kit's authored pivot placement (different scale/position math, non-door-pivot-aware) — this is a distinct code path from the "real" panel placement.
- `BuildCornerPosts(Points, Kit)` — one post per footprint vertex, oriented along the outgoing segment (the last point of an *open* run borrows the incoming segment's direction instead, since it has no outgoing one); same basic-cube-fallback special-case as walls.
- `BuildSlabs(Points, Kit)` — builds a `Levels` list pairing a Z height with a tile-size array: one entry per floor (using `FloorSet`) plus one roof entry at `FloorCount * FloorHeight` (using `RoofSet`), each only if the relevant `bGenerate*` flag is set and the tile set is non-empty; computes 2D polygon bounds; for each level, iterates a grid from `Bounds.Min.X`→`Bounds.Max.X` in `TopSize` steps and `Bounds.Max.Y`→`Bounds.Min.Y` in `-TopSize` steps (matching the tile's corner-pivot, +X/-Y-extent convention), calling `PlaceSlabCell` per grid cell.
- `PlaceSlabCell()` — recursive: if `IsCellInsidePolygon` passes at the current tile size, places one instance (again with a distinct basic-cube fallback transform vs. the real mesh's pivot-aligned transform); otherwise recurses into the next-smaller tile size, subdividing the cell into `round(Size/SubSize)`² sub-cells; if there's no next-smaller size, the partial cell is simply left empty (comment: the remaining sliver is narrower than the smallest tile and sits under wall thickness).
- `IsCellInsidePolygon()` — tests 4 corners + center, each inset by `min(0.5, Size*0.01)` — comment explains the inset is required because grid-aligned cell corners land exactly on the polygon edge where a crossing-number test is ambiguous, and without it the entire perimeter ring of tiles would falsely test as outside.
- `IsPointInPolygon()` — standard crossing-number (ray-casting) point-in-polygon test, works for any simple polygon regardless of convexity/winding.
- `ToData()`/`ApplyData()` — serialize/deserialize `BuildingId`, `Origin`/`Rotation` (from `GetActorLocation/Rotation`), `SplinePoints`, `bClosedLoop`, `FloorCount`, `KitAsset` (via `FSoftObjectPath`), `DoorSegmentIndex`; `ApplyData` suppresses regeneration mid-load and only regenerates/notifies once at the end if `bRegenerate`.
**Dependencies:** `Building/GRTBuildingKit.h`, `Core/GRTManager.h`, `Core/GRTSubsystem.h`, `Components/SplineComponent.h`, `Components/InstancedStaticMeshComponent.h`, `Engine/StaticMesh.h`, `Engine/World.h`, `CollisionQueryParams.h`, `Kismet/GameplayStatics.h`, `Net/UnrealNetwork.h` (`DOREPLIFETIME`), `GRTModule.h`.
**Notable implementation details:** Every mesh-placement site (`BuildWalls`, `BuildCornerPosts`, `PlaceSlabCell`) has a parallel "is this the `/Engine/BasicShapes/` fallback cube" branch (checked via `Mesh->GetPathName().Contains(TEXT("BasicShapes"))`) that computes a completely different scale/transform than the real authored-mesh path, because the engine cube's pivot (centered, unit size) doesn't match the kit's corner/base pivot convention — so kit-less or mesh-load-failure buildings render as boxes with independently-tuned placement math rather than reusing the panel-pivot transform.

### Plugins/GRT/Source/GRT/Public/Gizmo/GizmoManipulationMath.h
**Class/struct(s):** none (free functions/data only) — declares the `GizmoMath` namespace of pure functions
**Purpose:** Declares the pure, unit-testable math layer for the runtime transform gizmo: axis/plane resolution, ray/plane intersection, translate/rotate/scale delta computation from drag state, snapping, and hit-testing. No `UObject`/`UWorld`/`UPrimitiveComponent` references anywhere, matching this project's existing math-module pattern (`RoadCurveGraph`, `RoadElevationProfile`, `RoadSpiral`, `RoadPierPlacement`, `RoadXodrExport`).
**Key API / responsibilities:**
- `ResolveAxisDirection` / `ResolvePlaneNormal` — resolve a handle type to a world-space axis or plane normal, rotating by `TargetRotation` when `Space == Local`; return `ZeroVector` for handle types with no single axis/plane.
- `ResolveAxisDragPlane` — best-conditioned plane containing a given axis line for ray intersection, generalized from a prior world-Z-only special case.
- `ResolveTranslateDragPlane` — picks the drag plane per handle type (axis handles use `ResolveAxisDragPlane`, plane handles use their own normal, `Center` uses a camera-facing plane).
- `BestFacingVerticalPlaneNormal` — vertical-plane normal derived from the cursor ray's own horizontal projection, avoiding the degenerate "camera-to-point" approach when looking straight down.
- `IntersectRayWithPlane` — ray/plane intersection that explicitly fails (returns `false`) on a near-parallel ray instead of returning garbage.
- `ComputeTranslateDelta` — delta since drag start, axis-projected for axis handles, in-plane-clamped for plane handles, raw for `Center`.
- `ComputeRotationAngle` — signed radians around an axis via the "arc drag" technique, wrapped with `FMath::FindDeltaAngleRadians`.
- `ComputeRotationDelta` — wraps `ComputeRotationAngle` into a full `FQuat`, using `CameraForward` as the axis for `RotateScreen`.
- `ComputeScaleDelta` — per-component multiplicative ratio since drag start (clamped away from zero/negative via `MinDenominator`/`MinRatio`); `ScaleUniform` uses plain 3D distance, applied to all three components.
- `SnapValue` / `SnapVector` — generic (component-wise) rounding to an increment.
- `DistanceRayToSegment`, `DistanceRayToPoint`, `DistanceRayToRing`, `DistanceRayToQuad` — per-handle-shape hit-test distance functions, each also reporting `OutDistanceAlongRay` for nearest-to-camera tie-breaking; ring/quad return `TNumericLimits<double>::Max()` on a near-parallel ray.
**Dependencies:** `Gizmo/GizmoTypes.h` (`EGizmoHandleType`, `EGizmoCoordinateSpace`, `FGizmoInteractionRay`); otherwise only `CoreMinimal.h`.
**Notable implementation details:** Every delta function is documented as "initial transform + accumulated delta since drag start," never "current transform + this frame's delta" — deliberately avoiding compounding float drift over a long drag.

### Plugins/GRT/Source/GRT/Private/Gizmo/GizmoManipulationMath.cpp
**Class/struct(s):** none (free functions/data only) — implementation of the `GizmoMath` namespace
**Purpose:** Implements every function declared in `GizmoManipulationMath.h`.
**Key API / responsibilities:**
- `ResolveAxisDirection`/`ResolvePlaneNormal` switch on `EGizmoHandleType` to pick `XAxisVector`/`YAxisVector`/`ZAxisVector` (or the corresponding plane normal), then apply `TargetRotation.RotateVector` only in `Local` space.
- `BestFacingVerticalPlaneNormal` returns `FVector(CursorDir.X, CursorDir.Y, 0).GetSafeNormal()`, falling back to `FVector::ForwardVector` if that horizontal projection is nearly zero.
- `ResolveAxisDragPlane` computes `Normal = CursorDir - Axis * Dot(CursorDir, Axis)` (component of cursor dir perpendicular to the axis); if that's nearly zero it falls through `CrossProduct(Axis, CameraForward)` → `CrossProduct(Axis, UpVector)` → `CrossProduct(Axis, RightVector)` in sequence.
- `IntersectRayWithPlane` rejects when `|Dot(Ray.Direction, PlaneNormal)| < UE_KINDA_SMALL_NUMBER`, otherwise calls `FMath::RayPlaneIntersection`.
- `ComputeTranslateDelta` projects `RawDelta` onto the axis for axis handles, strips the out-of-plane component (`RawDelta - Normal * Dot(RawDelta, Normal)`) for plane handles, and returns `RawDelta` unmodified for `Center`.
- `ComputeRotationAngle` builds two basis vectors perpendicular to `Axis` (`CrossProduct(Axis, UpVector)`, falling back to `RightVector` if degenerate), computes `Atan2` angles for the start/current vectors relative to `GizmoOrigin`, and returns `FMath::FindDeltaAngleRadians(StartAngle, CurrentAngle)`. Returns `0.0` if either vector from origin is nearly zero or if both basis fallbacks degenerate.
- `ComputeScaleDelta` uses `constexpr double MinDenominator = 1.0` (cm) and `MinRatio = 0.01` to keep the ratio finite/positive; `ScaleUniform` divides `CurrentDist/StartDist` (both `Dist` from `GizmoOrigin`, `StartDist` floored at `MinDenominator`); per-axis scale signs the denominator via `FMath::Sign(StartOffset)` before flooring its magnitude, so the ratio's sign tracks which side of the origin the drag started on.
- `SnapValue` returns `Value` unchanged if `Increment <= 0.0`, else `RoundToDouble(Value/Increment) * Increment`.
- `DistanceRayToSegment` solves the standard closest-point-between-two-lines system (`A,B,C,D,E,Denom`), falls back to solving directly for `T = E/C` when lines are parallel (`|Denom| < UE_KINDA_SMALL_NUMBER`), clamps `T` into `[0, SegmentLength]`, then measures point-to-ray-line distance from that fixed segment point (documented as a simplification vs. true segment-segment closest point).
- `DistanceRayToRing` intersects the ray with the ring's plane, then returns `|Dist(Intersection, Origin) - Radius|`; on a failed intersection it sets both outputs to `TNumericLimits<double>::Max()`.
- `DistanceRayToQuad` computes the plane normal via `CrossProduct(AxisU, AxisV)`, intersects, converts the intersection to local `(U,V)` coordinates, and returns the Euclidean distance of the excess beyond `[-HalfSize, HalfSize]` in each axis (0 if inside).
**Dependencies:** Only its own header (`Gizmo/GizmoManipulationMath.h`), which pulls in `GizmoTypes.h`. Uses `FMath`, `FVector`, `FPlane`, `FQuat`, `TNumericLimits` from Core.
**Notable implementation details:** `DistanceRayToSegment`/`Point`/`Ring`/`Quad` all report `OutDistanceAlongRay` unconditionally (even on non-hit, ring/quad set it to `Max()`), which the subsystem later uses both as a hit filter (`AlongRay >= 0`) and a nearest-wins tiebreaker. `ComputeScaleDelta`'s per-axis path explicitly preserves sign across the origin crossing, unlike `ScaleUniform` which cannot (distance is always positive).

### Plugins/GRT/Source/GRT/Private/Gizmo/RuntimeGizmoActor.cpp

**Purpose:** Constructs, materials, and ticks the gizmo's visual handle meshes; implements mode switching, handle-type lookups, per-handle reach, and camera-distance-based auto-scaling plus the screen-space rotation ring's always-face-camera behavior.
**Key API / responsibilities:**

### Plugins/GRT/Source/GRT/Private/Gizmo/GizmoManipulationSubsystem.cpp
**Class/struct(s):** `UGizmoManipulationSubsystem` (implementation)
**Purpose:** Implements the subsystem's full manipulation lifecycle: gizmo actor spawning/teardown, target binding, hover/hit-testing against the live gizmo actor's component transforms, and per-mode (translate/rotate/scale) drag update logic built on top of `GizmoMath`'s pure functions.
**Key API / responsibilities:**
- `Deinitialize()` — destroys `GizmoActor` if present before calling `Super::Deinitialize()`.
- `GetGizmoActor() const` — returns `GizmoActor`.
- `EnsureGizmoActor()` — spawns one `ARuntimeGizmoActor` (`AlwaysSpawn` collision handling, `RF_Transient`) at `FTransform::Identity` if not already spawned; returns `nullptr` if `GetWorld()` fails.
- `GetPivotLocation() const` — returns `State.CustomPivot` for `Custom` pivot mode, else `State.GetTransformFn.Execute().GetLocation()` if bound, else the target's `GetComponentLocation()`, else `ZeroVector`.
- `UpdateGizmoTransform()` — sets the gizmo actor's location to the pivot; rotation is `FQuat::Identity` unless `Space == Local` and the get-transform delegate is bound, in which case it uses the target's actual rotation.
- `SetTarget(NewTarget)` — `nullptr` delegates to `ClearTarget()`; otherwise captures the target's owner as a `TWeakObjectPtr<AActor>` in lambdas for get/set (weak so a mid-session-destroyed target fails the accessor safely instead of dereferencing a dangling pointer), then calls `SetTargetTransformAccessors`.
- `SetTargetTransformAccessors(...)` — stores `State.Target`/`GetTransformFn`/`SetTransformFn`, unhides+enables tick on the gizmo actor and sets its mode, then calls `UpdateGizmoTransform()`.
- `ClearTarget()` — resets `State.Target`, unbinds both accessor delegates, resets `bIsManipulating`/`ActiveHandle`/`HoveredHandle`, and hides+disables-tick the gizmo actor and clears its highlight.
- `SetMode`/`SetCoordinateSpace`/`SetPivotMode` — update `State` and propagate to the gizmo actor / call `UpdateGizmoTransform()`.
- `FindHoveredHandle(Ray, CameraForward, OutHitPoint) const` — builds a candidate handle list per `State.Mode` (7 translate handles, 4 rotate, 4 scale), then for each candidate reads the handle's live `UPrimitiveComponent`'s `GetComponentTransform()` and dispatches to the matching `GizmoMath::DistanceRayTo*` function using that component's actual local axis (`GetUnitAxis(EAxis::Z)` for translate arrows since Cylinder/Cone point along local Z; `GetUnitAxis(EAxis::X)` for scale/rotate since the migrated meshes' primary axis is local X). Tolerance is `ClickTolerance(20.0) * GizmoActor->GetActorScale3D().X`. Keeps the best candidate by requiring `Dist <= Tolerance && AlongRay >= 0.0 && AlongRay < BestAlongRay` — nearest-to-camera wins among all handles within tolerance, and a handle whose closest approach is behind the ray origin is explicitly rejected.
- `UpdateHover(Ray, CameraForward)` — returns `None` immediately if already manipulating or no valid target; otherwise calls `FindHoveredHandle`, stores it as `State.HoveredHandle`, and calls `GizmoActor->SetHighlightedHandle`.
- `BeginManipulation(Ray, CameraForward)` — returns `None` if `GetTransformFn` isn't bound; otherwise finds the hovered handle, and if one was hit, sets `ActiveHandle`, `bIsManipulating=true`, captures `InitialTransform` (via `GetTransformFn.Execute()`), `InitialRay`, `InitialIntersection` (the hit point), sets the highlight, and broadcasts `OnManipulationBegin`.
- `UpdateManipulation(Ray, CameraForward, bInvertSnapForThisCall)` — no-ops if not manipulating or `SetTransformFn` unbound. Computes `bEffectiveSnapping` via XOR of the persistent flag and the per-call invert flag. Uses `State.InitialTransform`'s location/rotation as `Origin`/`TargetRotation` (fixed for the whole drag). Per mode, resolves a drag plane/ring plane and intersects the ray against it (Translate uses `ResolveTranslateDragPlane`; Rotate builds a ring plane from the resolved rotation axis, with `RotateScreen` using camera forward; Scale uses a camera-facing plane for `ScaleUniform` or `ResolveAxisDragPlane` for a specific axis). If intersection fails, returns without modifying anything. Then computes the delta via the matching `GizmoMath::Compute*Delta` function, applies snapping if `bEffectiveSnapping` (`SnapVector` for translate/scale ratio, degree-based `SnapValue` for rotation angle), builds `NewTransform` from `InitialTransform` with the delta applied, and calls `State.SetTransformFn.Execute(NewTransform)`. Calls `UpdateGizmoTransform()` afterward only for Translate/Rotate — explicitly not for Scale, so scaling the target doesn't also grow/shrink the gizmo.
- `EndManipulation()` — no-op if not manipulating; otherwise clears `bIsManipulating`/`ActiveHandle` and broadcasts `OnManipulationEnd` with the target.
- `CancelManipulation()` — no-op if not manipulating; otherwise restores the target's transform to exactly `State.InitialTransform` via `SetTransformFn.Execute` (if bound), clears manipulation state, calls `UpdateGizmoTransform()`, and broadcasts `OnManipulationCancel`.
**Dependencies:** `Gizmo/RuntimeGizmoActor.h`, `Gizmo/GizmoManipulationMath.h`, `Engine/World.h`, `GameFramework/Actor.h`.
**Notable implementation details:** `ClickTolerance = 20.0` is a file-local anonymous-namespace constant, explicitly documented as distinct from `ARuntimeGizmoActor::GetHandleReach` (which is a handle's own geometric SIZE, an input to the distance functions, not a tolerance on their output) — the two are multiplied together conceptually but computed/scaled independently (`ClickTolerance * ActorScale`, `Reach` already pre-scaled by the actor internally). The rotate-axis and scale-axis hit tests both read the handle component's live local-X axis at hit-test time rather than re-deriving it from `GizmoMath::ResolveAxisDirection`, matching the header's documented design choice to trust the rendered actor's actual transforms for hit-testing while keeping the delta math itself decoupled and pure.

### Plugins/GRT/Source/GRT/Private/IO/GRTArchiveHelper.cpp
**Class/struct(s):** `FGRTArchiveHelper` (implementation)
**Purpose:** Implements archive detection and extraction so a user-supplied `.tar.gz`/`.tgz`/`.zip`/`.tar` raster download can be transparently unpacked and matched to the correct GeoTIFF file for a given `EGRTRasterLayer`, without the caller needing to know archive internals.
**Key API / responsibilities:**
- `IsArchiveFile` — case-insensitive suffix match against `.tar.gz`, `.tgz`, `.zip`, `.tar`.
- `HasSupportedExtension` — true if `HasTiffExt` (local helper checking `.tif`/`.tiff`) or `IsArchiveFile` is true.
- `ResolveOrExtractRaster`:
  - Fails with an error string if `InputPath` is empty or the file doesn't exist (`FPaths::FileExists`).
  - If the input is already a `.tif`/`.tiff`, returns it directly (no extraction).
  - If not a recognized archive either, fails with an "Unsupported file format" error naming the allowed extensions.
  - Otherwise computes a destination cache folder `Saved/ExtractedRasters/<ArchiveBaseName>` (stripping `.tar` twice for `.tar.gz`/`.tgz` so the base name doesn't retain `.tar`), creates it via `IFileManager::Get().MakeDirectory(..., true)`.
  - Checks for already-extracted `.tif`/`.tiff` files recursively in that folder first (idempotent re-use of a prior extraction) before invoking the extractor.
  - Extracts using the OS `tar.exe` (`C:\Windows\System32\tar.exe` if present, else relies on `tar.exe` being on `PATH`) via `FPlatformProcess::ExecProcess` with args `-xf "<input>" -C "<destdir>"`; treats nonzero return code or a failed exec as an error, embedding stdout/stderr in the error message.
  - Re-scans the destination folder for `.tif`/`.tiff` after extraction; fails if still none found.
  - When multiple TIFFs are found, picks by keyword match against the layer's keyword (`GetLayerKeyword`: `dem`, `hillshade`, `color-relief`, `hillshade-color`, `slope`, `aspect`, `roughness`, empty for unmatched layers) via filename `Contains(..., ESearchCase::IgnoreCase)`.
  - Special-cases `EGRTRasterLayer::Elevation`: if still ambiguous, prefers a filename containing `"output"`.
  - Falls back to the first found TIFF if no better match.
**Dependencies:** `IO/GRTArchiveHelper.h` → `IO/GRTRasterLayers.h` (for `EGRTRasterLayer`); engine `HAL/FileManager.h` (`IFileManager`), `HAL/PlatformProcess.h` (`FPlatformProcess::ExecProcess`), `Misc/Paths.h` (`FPaths`).
**Notable implementation details:** Extraction shells out to the Windows-bundled `tar.exe` rather than any bundled/cross-platform archive library, so this is effectively Windows-only (or dependent on `tar` being present on `PATH` elsewhere). The "already extracted" check means a stale/partial extraction from a previous run will short-circuit re-extraction — there is no hash/size validation against the source archive, just presence of any `.tif`/`.tiff` in the target folder.

### Plugins/GRT/Source/GRT/Private/IO/GRTRasterLayers.cpp
**Class/struct(s):** none (free functions/data only) — implements the `GRTRasterLayers` namespace declared in the corresponding header
**Purpose:** Provides UI-facing display names for `EGRTRasterLayer` values, band-count validation for slotting a raster into a given layer type, and filename/band-count heuristics to auto-detect what kind of raster product a given GeoTIFF file is (DEM, hillshade, slope, aspect, roughness, color relief, color hillshade, or satellite/ortho) so an import UI can pre-select the right layer type.
**Key API / responsibilities:**
- `GetDisplayName(EGRTRasterLayer)` — returns a localized `FText` label for each layer enum value (e.g. "Elevation (DEM)", "Color Hillshade"), falling back to "Unknown".
- `IsBandCountValidFor(Layer, BandCount, OutReason)` — rejects a zero/negative band count outright; for `Elevation` layers requires exactly 1 band and produces an explanatory message distinguishing "no bands" from "looks like a colour image (hillshade/relief) rather than a DEM"; all other layer types accept any positive band count (single-band greyscale through multi-spectral).
- `AutoDetectRasterType(FilePath, OutType, OutTypeLabel, OutInfo, OutError)` — calls `FGRTGeoTIFFReader::ProbeMetadata` to get band count cheaply, then classifies by band count first and filename substring second: 1-band files are matched against `"slope"`, `"aspect"`, `"roughness"/"tri"/"tpi"`, `"hillshade"/"shade"`, `"dem"/"elevation"/"dtm"/"dsm"` (in that priority order), defaulting to Hillshade/Analytical if nothing matches; 3+/other band-count files are matched against `"color-hillshade"` variants, `"relief"` variants, or satellite-ish tokens (`"sat"`, `"ortho"`, `"rgb"`, `"truecolor"`, `"sentinel"`, `"landsat"`), defaulting to Satellite/Ortho (Multi-Band) or Multi-Band Composite.

**Notable implementation details:** Classification is purely metadata + filename heuristics — it never opens pixel data, so it's effectively free even on huge files. Band-count check runs before any filename check, and within a band-count bucket the match order matters (e.g. a filename containing both "hillshade" and "color" would be caught by the `color-hillshade` check before the plain "hillshade" one, since those are only checked in the 1-band branch, not the 3+ branch, ensuring they never collide).

### Plugins/GRT/Source/GRT/Public/IO/GRTGeoTIFFReader.h
**Class/struct(s):** `FGRTGeoTIFFRaster` (struct), `FGRTRasterInfo` (struct), `FGRTGeoTIFFReader` (class, `GRT_API`)
**Purpose:** Declares the data types and static reader API for decoding GeoTIFF elevation/imagery rasters through GDAL — a full-decode struct (`FGRTGeoTIFFRaster`) for single-band elevation, a header-only-probe struct (`FGRTRasterInfo`) for fast multi-layer validation without touching pixels, and the reader class itself with static entry points for loading elevation, probing metadata, and decoding arbitrary raster imagery to textures/pixel buffers.
**Key API / responsibilities:**

- `FGRTGeoTIFFReader::DecodeRasterPixels(FilePath, MaxDimension, OutPixels, OutWidth, OutHeight, OutError)` — decodes into an `FColor` buffer, applying GIS colormaps to Float32 analysis layers (slope/aspect/roughness).

**Notable implementation details:** Comments document that pixel (0,0) is the *centre* of the top-left sample under GeoTIFF's `RasterPixelIsArea` convention, and that the CRS support is deliberately narrowed to geographic WGS84 or standard UTM zones because that's all `FGRTGeoTIFFHeightSource`'s Cesium bridge implements downstream.

**Class/struct(s):** implements `FGRTGeoTIFFRaster`, `FGRTRasterInfo`, `FGRTGeoTIFFReader` (declared in the header above)
**Purpose:** The actual GDAL-backed implementation: registers GDAL's driver registry and PROJ/GDAL resource paths once per process, opens files via `GDALOpen`, reads/validates georeferencing and CRS, decodes single-band elevation with NoData handling, and decodes arbitrary imagery (RGB/RGBA/greyscale/float analysis bands) into colorized `FColor` pixel buffers or `UTexture2D`.

- `EnsureGdalRegistered()` (anonymous-namespace helper) — one-time `GDALAllRegister()`, and points `PROJ_DATA`/`GDAL_DATA` config options at `<Plugin>/Binaries/Win64/GDALResources/{proj,gdal}` if those directories exist.

- `DecodeRasterToTexture` — calls `DecodeRasterPixels`, creates a transient `PF_B8G8R8A8` `UTexture2D` via `UTexture2D::CreateTransient`, sets `SRGB=true`, `TC_Default` compression, bilinear filter, memcpys pixel data into the locked mip 0, calls `UpdateResource()`, and logs the result.

### Plugins/GRT/Source/GRT/Private/IO/GRTGeoTIFFHeightSource.cpp
**Class/struct(s):** implements `FGRTGeoTIFFHeightSource` (declared above); also contains free helper functions `LonLatToUTM`/`UTMToLonLat`/`CentralMeridianRad` in an anonymous namespace
**Purpose:** Full implementation of the GeoTIFF-to-Cesium-world height bridge: hand-implemented forward/inverse UTM↔lon/lat transforms (WGS84 ellipsoid, Snyder's series), georeference-origin placement so imported terrain lands at its true real-world altitude, world-footprint computation, and NoData-safe bilinear height sampling.
**Key API / responsibilities:**
- `LonLatToUTM` / `UTMToLonLat` (anonymous-namespace) — forward and inverse Transverse Mercator using WGS84 constants (`UTM_A=6378137.0`, `UTM_F=1/298.257223563`, `UTM_K0=0.9996`), Snyder's standard UTM series truncated for sub-metre accuracy within one zone (explicitly documented as not survey-grade); `LonLatToUTM` adds 10,000,000 m false northing for southern-hemisphere zones.
- `WorldXYToRasterCrs(WorldX, WorldY, OutCrsX, OutCrsY)` — transforms Unreal world position to lon/lat via `ACesiumGeoreference::TransformUnrealPositionToLongitudeLatitudeHeight`, then either passes lon/lat through directly (geographic raster) or converts to UTM easting/northing (UTM raster) via `LonLatToUTM`.
- `Initialize` — moves the raster in; resolves `ACesiumGeoreference::GetDefaultGeoreference(World)` (tag `DEFAULT_GEOREFERENCE`, then name `CesiumGeoreferenceDefault`, then any instance, per the header's doc comment); computes the raster's geographic centre by converting the pixel-space centre `((Width-1)/2, (Height-1)/2)` through `PixelToCrs` then to lon/lat; computes `ZScale` as either `OverrideZScaleOrZero` or `RangeMeters * 100.0 / (1.0 - 2*ClampedHeadroom)` (headroom clamped to [0, 0.4]); computes `ElevationFloorMeters = Min - Range*Headroom`; computes `OriginElevationMeters` via `SampleElevationMetersAtPixelOrFallback` at the centre pixel, falling back to the min/max midpoint if the centre sample is NoData; if `bEstablishGeoreferenceOrigin`, calls `Ref->SetOriginLongitudeLatitudeHeight(lon, lat, OriginElevationMeters)` — using the real centre altitude rather than 0, which the comment says is what makes the import land at true elevation instead of flattening onto the sea-level tangent plane; computes `WorldFootprintXY` by transforming all 4 raster corner pixels (not just 2, to correctly bound a rotated/sheared affine) through CRS→lon/lat→`TransformLongitudeLatitudeHeightPositionToUnreal` and accumulating an `FBox2D`; logs a detailed summary via `LogGRT`.
- `SampleElevationMetersAtPixelOrFallback(Col, Row, Fallback)` — rounds/clamps to a valid pixel index and returns the sample if valid, else `Fallback`.
- `TrySampleWorldXY` — checks `WorldFootprintXY.IsInside`, converts to raster CRS then to fractional pixel coords via `Raster.CrsToPixel`, rejects if outside `[0,Width-1]×[0,Height-1]`, then does bilinear interpolation across the 4 surrounding samples (`S00,S10,S01,S11`) — but refuses (`return false`) the whole sample if ANY of the 4 contributing cells is NoData, rather than interpolating through it; normalizes the result to `[0,1]` via `(ElevationMeters - ElevationFloorMeters) / ElevationRangeMeters`, clamped.
- `TrySampleRasterPixel` — same footprint/CRS/pixel-bounds checks as `TrySampleWorldXY` but returns the raw fractional pixel coordinates instead of a sampled/normalized height.
**Dependencies:** `GRTModule.h` (`LogGRT`), `Engine/World.h`, `CesiumGeoreference.h` (`ACesiumGeoreference::GetDefaultGeoreference`, `TransformUnrealPositionToLongitudeLatitudeHeight`, `SetOriginLongitudeLatitudeHeight`, `TransformLongitudeLatitudeHeightPositionToUnreal`), and the header above.
**Notable implementation details:** Confirms the project's documented ESU/Cesium convention indirectly by relying entirely on Cesium's own transform functions rather than any hand-rolled ENU math. The bilinear sampler's all-or-nothing NoData policy is explicit and deliberate — comment explains that blending one NoData sentinel with real neighbours "produces a hole punched kilometres deep" rather than a plausible height, so it's better to fail the sample and let the caller decide (fill from neighbours, or leave the chunk procedural). The georeference-origin altitude is taken from the DEM's actual centre *sample* (not the numeric midpoint of min/max) specifically so Z=0 lands on real ground rather than potentially thin air halfway up a slope on a DEM spanning both a valley floor and a ridge.

### Plugins/GRT/Source/GRT/Private/Physics/GRTCollision.cpp
**Class/struct(s):** none (implements methods of `UGRTCollisionLib`)
**Purpose:** Implements the three declared library functions: syncing a dynamic mesh's vertex heights from a CPU height cache, configuring a `UDynamicMeshComponent` as an invisible Chaos-physics terrain collider, and testing whether a given local-space location on that mesh falls in a "hole" (non-zero MaterialID) region.
**Key API / responsibilities:**
- `ApplyHeightDataToMesh`: early-returns if `TargetMeshComp`/its `GetDynamicMesh()` is null, or if `HeightData.Num() != Resolution*Resolution`. Otherwise calls `GetDynamicMesh()->EditMesh(...)` and, for every vertex in the mesh, converts the vertex's local X/Y (mesh centered on origin, range `[-ChunkSize/2, +ChunkSize/2]`) into a `[0,1]` UV, maps that to a nearest-neighbor grid index via `FMath::RoundToInt(U * (Resolution-1))` clamped to `[0, Resolution-1]`, looks up `HeightData[GridY*Resolution + GridX]`, and calls `Mesh.SetVertex(VertID, FVector3d(Pos.X, Pos.Y, NewZ))` — X/Y are left untouched, only Z is replaced. A comment notes `ZScale` is "usually already baked into float cache" (the `ZScale` parameter itself is unused in the body). Vertex-normal recompute is present only as a commented-out call (`FMeshNormals::QuickComputeVertexNormals`). The `EditMesh` call passes `EDynamicMeshChangeType::GeneralEdit` and `EDynamicMeshAttributeChangeFlags::VertexPositions`.
- `ConfigureForTerrainPhysics`: null-checks `TargetComponent`; sets `CollisionType = ECollisionTraceFlag::CTF_UseComplexAsSimple`; disables shadows (`SetCastShadow(false)`, `bCastDynamicShadow = false`, `bCastStaticShadow = false`); hides the component (`SetVisibility(false)`, `SetHiddenInGame(true)`); enables navigation via `SetCanEverAffectNavigation(true)`; and sets the collision profile to `"BlockAll"`.
- `IsLocationTraceable`: null-checks the mesh; calls `ProcessMesh` (read-only) and defaults `bIsTraceable = true`. Inside: bails (traceable) if `TriangleCount()==0` or mesh bounds have zero X/Y extent. Computes `Resolution = round(sqrt(VertexCount()))` (treating the mesh as a single top-surface grid, no separate bottom slab), bails if `Resolution < 2`. Normalizes `LocalLocation` into `[0,1]` against the mesh bounds and bails "traceable" if out of `[0,1]` range. Maps to a clamped grid cell `(CellX, CellY)`, computes an expected top-surface triangle count `2*(Resolution-1)^2`, and if the mesh has fewer triangles than that, bails traceable (assumes layout mismatch). Otherwise computes `TriBase = (CellY*(Resolution-1)+CellX)*2` and inspects the mesh's `MaterialID` triangle attribute (if present) on the two triangles at `TriBase` and `TriBase+1`: if either has a non-zero MaterialID, sets `bIsTraceable = false`. If there is no MaterialID attribute layer at all, the location is treated as traceable (no holes possible).
**Dependencies:** `Components/DynamicMeshComponent.h`, `GeometryScript/MeshSpatialFunctions.h`, `UDynamicMesh.h`, `DynamicMesh/DynamicMesh3.h`, `DynamicMesh/MeshNormals.h`. Comments reference `AGRTChunk::RebuildMesh` as the mesh-generation source whose triangle-append ordering this function's grid-cell-to-triangle-index math depends on.
**Notable implementation details:** A large inline comment documents a fixed prior bug: `IsLocationTraceable` used to divide vertex count by 2 assuming a "top + bottom slab" mesh, which understated `Resolution` by a factor of `sqrt(2)`, silently mis-indexing into an unrelated grid cell's MaterialID — and critically, the resulting under-count still passed the "mesh layout mismatch" guard (`TriangleCount() < ExpectedTopTris`), so that guard didn't catch the error either. The triangle-ID math is a hard-coded assumption (documented in-code) that top-surface triangles are appended first, 2 per cell, in row-major (Y outer, X inner) order by `RebuildMesh()` — if that generation order ever changes, this lookup silently breaks again with no runtime detection. `ApplyHeightDataToMesh` uses nearest-neighbor sampling only (no bilinear interpolation), explicitly called out in comments as a deliberate speed/quality tradeoff acceptable for collision meshes.

### Plugins/GRT/Source/GRT/Private/Physics/GRTMeshUtils.cpp
**Class/struct(s):** none (implements methods of `UGRTMeshUtils`)
**Purpose:** Implements grid-mesh generation, hole punching via per-triangle MaterialID assignment, and normal recomputation, all via GeometryScript library calls and direct `FDynamicMesh3` editing.
**Key API / responsibilities:**
- `GenerateTerrainGrid`: null-checks `TargetMesh`, calls `TargetMesh->Reset()`, builds `FGeometryScriptPrimitiveOptions` with `PolygroupMode = PerFace` and `UVMode = Uniform`, then calls `UGeometryScriptLibrary_MeshPrimitiveFunctions::AppendRectangleXY(TargetMesh, Options, FTransform::Identity, Size, Size, Resolution, Resolution)` to build a square XY grid centered at the identity transform. If `MaterialID != 0`, builds an "all triangles" `FGeometryScriptMeshSelection` and calls `SetMaterialIDForMeshSelection` to stamp every triangle with that material ID.
- `UpdateHoleAtLocation`: calls `TargetMesh->EditMesh(...)`. Inside the lambda: ensures the mesh has an attribute layer (`Mesh.EnableAttributes()` if missing) and ensures a MaterialID attribute exists (`Mesh.Attributes()->EnableMaterialID()` if missing), fetching `MatAttrib`. Computes `RadiusSq` and a 2D `Center2D` from `LocalCenter.X/Y`. `TargetID = bRefill ? 0 : HoleMaterialID`. Iterates every triangle via `Mesh.TriangleIndicesItr()`, computes each triangle's 2D centroid from its 3 vertices, and if `DistSquared(Centroid, Center2D) <= RadiusSq`, calls `MatAttrib->SetValue(TriID, TargetID)`. The `EditMesh` call passes `EDynamicMeshChangeType::AttributeEdit` and `EDynamicMeshAttributeChangeFlags::TriangleGroups` (a code comment flags this flag choice as a deliberate fix: `<-- FIXED: Use TriangleGroups for material ID changes`).
- `RecomputeNormals`: null-checks `TargetMesh`, calls `UGeometryScriptLibrary_MeshNormalsFunctions::ComputeSplitNormals(TargetMesh, FGeometryScriptSplitNormalsOptions(), FGeometryScriptCalculateNormalsOptions())` with default option structs.
**Dependencies:** `UDynamicMesh.h`, `GeometryScript/MeshPrimitiveFunctions.h`, `GeometryScript/MeshMaterialFunctions.h`, `GeometryScript/MeshNormalsFunctions.h`, `GeometryScript/GeometryScriptSelectionTypes.h`, `DynamicMesh/DynamicMesh3.h`, `DynamicMesh/DynamicMeshAttributeSet.h`, `DynamicMesh/DynamicMeshChangeTracker.h` (included twice, at lines 19 and 21), `Math/Vector.h`.
**Notable implementation details:** Hole detection/marking in `UpdateHoleAtLocation` is centroid-based per triangle (not per-vertex, not exact circle-triangle intersection) — a triangle is entirely included or excluded from the hole based solely on whether its centroid falls within `Radius` of `LocalCenter`, which can leave a jagged/approximate hole boundary at low mesh resolution. `MaterialID 0` is treated project-wide as "ground/no hole" by convention (used both as the default ground ID in `GenerateTerrainGrid` and as the refill target in `UpdateHoleAtLocation`), matching the "non-zero MaterialID = hole" convention read by `IsLocationTraceable` in `GRTCollision.cpp`.

**Class/struct(s):** `UGRTBaker` (implementation)
**Purpose:** Implements the landscape→`UGRTTileData` bake pipeline: walks a landscape's components, creates one data asset per component populated with real-world size, Z scale, grid coordinate, and extracted heightmap/weightmap data.
**Key API / responsibilities:**
- `BakeLandscapeToAssets` — iterates `SourceLandscape->LandscapeComponents`, auto-names each as `TD_Tile_<SectionBaseX>_<SectionBaseY>`, calls `BakeComponent` per component, collects and logs the results.

**Notable implementation details:** The comment above `ExtractHeightmapData`'s pixel loop notes "Assuming BGRA format (Typical)" and "channel order depends on platform" — the R/G-channel decode is an assumption, not a verified format check. The auto-save-to-disk code path (`UPackage::SavePackage`) is present but fully commented out, so baked assets are only registered/dirtied in memory, not written to disk, by this function alone. `ExtractWeightmapData` is implemented but is dead code from `BakeComponent`'s perspective — it's never called in the bake pipeline, so weight/paint-layer data is never actually baked into `UGRTTileData` despite the extraction logic existing and working against real component data.

**Notable implementation details:** File-header comments state this suite mirrors an older test (`GRT.Building.GizmoRuntimeAssets` in `GRTBasicTests.cpp`, not part of this batch) that had already caught two runtime-cooking bugs in the previous (now-stripped) gizmo actor — a `Transient` mesh property invisible to the cooker, and MIDs built in the constructor and shared across instances via the CDO — and re-verifies both are still avoided in `ARuntimeGizmoActor`'s fresh implementation.
### Plugins/GRT/Source/GRT/Public/Core/GRTSaveGame.h
**Class/struct(s):** `UGRTSaveGame` (UCLASS, extends `USaveGame`); `FGRTChunkData`, `FGRTLandscapeLayerMapping`, `FGRTGeoTIFFImportState`, `FGRTLandscapeMigrationState` (USTRUCTs).
**Purpose:** Defines the complete on-disk save format for a GRT world — every chunk's height/weight-layer data, foliage/population/building state, and which of the three origin paths (Procedural, ImportedLandscape, ImportedGeoTIFF) produced the world, so a reload can reconstruct the exact same terrain and content without re-running import/generation.
**Key API / responsibilities:**
- `FGRTChunkData` — one chunk's `HeightData` plus the three separate `BaseData`/`SculptData`/`DetailData` height layers (kept alongside the legacy combined `HeightData` for graceful fallback on old saves), and per-chunk foliage arrays split between "transferred from a Landscape import" and "placed via GRT actor foliage" — each with its own transform/material/mesh-path arrays since they're reconstructed through different code paths.
- `EGRTChunkOrigin` (Procedural/ImportedLandscape/ImportedGeoTIFF) — `UGRTSaveGame::WorldOriginKind` records which import path built the world; the doc comment notes old saves default to `Procedural` (the field didn't exist yet) and `ApplyLoadedSaveGame` infers `ImportedLandscape` from `LandscapeMigration.bWasImportedFromLandscape` as a legacy fallback.
- `FGRTGeoTIFFImportState`/`FGRTLandscapeMigrationState` — mirror-shaped metadata blocks for the two import origins (source file/path, world footprint or source Landscape transform, resolved Z-scale, per-layer weight-layer mappings), only one of which is meaningful per save depending on `WorldOriginKind`.
- `UGRTSaveGame` top level — `Chunks` (`TMap<FIntPoint, FGRTChunkData>`), `Buildings`, `AuthoredChunkCoords`, plus the full population/spawn-rule/biome/AI-zone/build-permission arrays declared in `GRTWorldTypes.h` (`ProceduralWorldSettings`, `BiomeOverlays`, `PopulationSpawnRules`, `AISpawnZones`, `BuildPermissionZones`, `ProceduralChunks`, `PersistentPopulationEntries`).
**Dependencies:** `GameFramework/SaveGame.h` (engine base class), `Core/GRTWorldTypes.h` (population/procedural struct types embedded here), `Building/GRTBuildingTypes.h` (`FGRTBuildingData`).
**Notable implementation details:** Every field defaults to a zero/empty value rather than being left uninitialized, which is what makes the "old saves silently get a sane default for a newly-added field" legacy-compatibility pattern referenced in the `WorldOriginKind` comment actually work — USTRUCT/enum fields not present in an old serialized save are zero-initialized by Unreal's loader rather than left garbage.

### Plugins/GRT/Source/GRT/Public/Core/GRTWorldTypes.h
**Class/struct(s):** none (pure data header — enums, USTRUCTs, and dynamic multicast delegate declarations only, no class).
**Purpose:** Central data-model header for GRT's procedural world-population system — defines what a "population" (a placeable prop/harvestable/destroyable/runtime-placed/procedural-spawn entity) is, how spawn rules and biome overlays decide where they appear, and the change-notification delegates other systems subscribe to.
**Key API / responsibilities:**
- `EGRTPopulationKind`/`EGRTPopulationState`/`EGRTBuildPermission` — the three core enums: what kind of population entity, its current lifecycle state (Active/Harvested/Destroyed/Regrowing), and a per-zone build-permission override (Inherit/Allowed/Blocked).
- `FGRTPopulationDescriptor` — the authoring-time template for a population entity: actor/mesh/material soft references, replication/attach/terrain-snap flags, regrowth delay, biome tag.
- `FGRTPersistentPopulationEntry` — one actually-spawned, saved population instance: a `FGuid` identity, its descriptor, chunk coordinate, local transform, current state, remaining regrowth timer, and which spawn rule (if any) produced it.
- `FGRTPopulationSpawnRule` — procedural spawn-rule parameters: min/max distance from authored chunks, min/max instances per chunk, required biome tag, spacing/padding.
- `FGRTBiomeOverlay` — a named biome region with noise-range gating and a priority for overlap resolution, applicable to authored and/or procedural chunks independently.
- `FGRTProceduralWorldSettings` — world seed, whether seeded outskirts / infinite edge growth are enabled, outskirts extent, and whether population auto-generates from rules.
- `FGRTProceduralChunkState` — per-chunk bookkeeping for the procedural-outskirts system: seed, authored/generated/population-generated flags, distance from the nearest authored chunk, primary/overlay biome tags.
- `FGRTAISpawnZone`/`FGRTBuildPermissionZone` — bounding-box-gated zones for AI spawn caps and build permission overrides.
- `FGRTPCGPoint` — a single PCG (Procedural Content Generation) sample point: transform, biome tag, source id, population kind, density — the hand-off shape between GRT's own population logic and Unreal's PCG framework.
- `FGRTTerrainChangeEvent`/`FGRTFoliageChangeEvent`/`FGRTPopulationChangeEvent` + their three `DECLARE_DYNAMIC_MULTICAST_DELEGATE` pairs — Blueprint-visible change notifications for terrain edits, foliage-instance-count changes, and population lifecycle changes.
- `FGRTWorldModeChosenDelegate` — fires exactly once, when `AGRTManager::MarkWorldModeChosen()` resolves the player's Sandbox/Import choice; its doc comment explains the reason it exists as a delegate rather than a polled flag: it lets a demo/showcase sequence wait for the real player choice instead of racing `BeginPlay` order or (worse) calling `MarkWorldModeChosen()` itself just to unblock its own startup, which would silently resolve the choice for the player before they ever see it.
**Dependencies:** `UObject/SoftObjectPtr.h` (all the `TSoftClassPtr`/`TSoftObjectPtr` fields); forward-declares `AActor`/`UMaterialInterface`/`UStaticMesh` rather than including their full headers, keeping this a lightweight, widely-includable data header.
**Notable implementation details:** `FGRTBiomeOverlay` has a stray blank double-line between its first `UPROPERTY` and the rest (cosmetic only, no functional effect). Every zone-bounds field (`FGRTAISpawnZone::LocalBounds`, `FGRTBuildPermissionZone::LocalBounds`) defaults to the same hardcoded 100m-ish box (`±5000,±5000,-500..5000`), so a newly-added zone is immediately meaningful in the editor rather than starting as a degenerate zero-size box.
